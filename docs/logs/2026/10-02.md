## 通用 JSON 合并 / 差量工具落地（plan 526）

### 起因

对比 `~/sources/json-render`（vercel-labs，flat elements + RFC 6902 patch 流）与 `~/app/nop-entropy` 的 Delta 机制（`nop-core/lang/json/delta`）时确认：NOP 的合并是**显式 schema-free** 的（`JsonMerger.java:28` 类注释"不依赖schema，直接对任意json进行merge操作"），identity 与列表形态全部运行时从数据发现（`DeltaMergeHelper.buildUniqueKey:235-264`、`DeltaJsonNormalizer.getListKind:48`），一套代码服务 i18n.yaml / amis 页面 JSON / scheduler.yaml / module-meta.json / ORM xdsl 五种互不相关格式。flux 侧核对：`diffSchemaInput` / `applyTreePatches` 唯一生产消费者是 `page-designer-core/src/session.ts:68-69`（undo/redo 栈），仓库内无任何 schema 合并语义。

结论：这是通用工具能力，不是 flux schema 特性，故落 `packages/flux-core/src/json-merge/`，签名与实现零 Flux schema 类型依赖。

### 落点

- 新增 `packages/flux-core/src/json-merge/`：`types.ts`（契约 + 默认值）/ `identity.ts`（identity 链 + `classifyList`）/ `list-order.ts`（`planListMerge` 锚点式顺序重建）/ `merge-json.ts`（合并引擎）/ `diff-delta.ts`（最小差量提取）/ `index.ts`。
- `packages/flux-core/src/index.ts` 新增导出（`mergeJson` / `diffToDelta` / `classifyList` / `readIdentity` / `planListMerge` + 4 个默认常量 + 9 个类型）。
- owner doc：`docs/architecture/flux-core.md` 新增「Schema-Agnostic JSON Merge / Delta Utility」章节（API、合并语义表、身份解析、差量提取、配置项、与 tree-patch 的分工）。
- plan：`docs/plans/2026-10-02-526-generic-json-merge-delta-plan.md`。

### 相对参考实现的三处改动（均为改进，非等价移植）

1. **identity 链可注入**：`options.identityKeys` 默认 `['xui:id','id','name']`，`options.uniqueAttrKey` 提供间接寻址。参考实现硬编码 5 级链（`x:unique-attr`/`x:id`/`v:id`/`id`/`name`），因其需跨格式通吃；TS 侧做成策略才能对接不同命名空间。
2. **`ALL_WITH_ID` 静默降级改为可观测**：参考实现 `JsonMerger.java:219` 在 base 列表未全带身份时直接 `return listB`（整段替换，无任何提示）。本实现产出 `list-not-keyed` 诊断（含 RFC 6901 path 与 listKind），另加 `duplicate-identity` 诊断。工具**从不抛异常**——所有降级走 diagnostics。
3. **标记键可配置，且不引入 `!` 前缀**：`options.markers` 默认 `xui:override` / `xui:virtual`。参考实现的 `"!xxx":yyy` 强制覆盖前缀会占用任意 JSON 文档的合法键空间，故 `forceOverridePrefix` 默认禁用（启用时语义为整段替换，与参考实现一致）。

另有两处语义偏离参考实现，已在 owner doc 记录：空 delta 数组表达"显式空列表"（参考实现视为"不变"，本实现改为与"键缺省=不变"正交）；identity 列表的差量按 resolved 顺序**完整输出并带身份戳**（部分列表无法表达重排序）。
