## standard-crud picker 弹框空白修复（v3 迁移遗漏）+ page-schemas 编译期验证门禁

### 落地内容

**问题**（docs/testing/2026/10-10.md #40）：`#/complex-pages/standard-crud` 新增/编辑弹框中「选择部门/选择标签」picker 弹框完全空白（只有标题和按钮，body 空容器，无报错）。根因是 2026-09-02 picker v3 重构的**迁移遗漏**：v3 把弹框内容唯一入口收敛到 `pickerSchema` region 并移除默认内容构建（G1），迁移提交 6fec8497e 只改了 `pickerDialog→pickerPopup` 名称，schema 里的 `loadAction`+`columns`+`valueKey`/`labelKey`+`searchable` 成为被 v3 渲染器**静默忽略的死属性**——弹框打开但内容为空。静默的机制根因：SchemaRenderer 编译默认收集 diagnostics（closed-model 渲染器如 picker 对死属性发 unknown-property），但 `compile()` 只返回 template、`continueOnError: true` 永不 throw、无任何消费者输出——死属性静默无响，数月未被发现（既有 e2e 只断言「弹框打开」未断言「有内容」）。

**修复**：standard-crud.json 4 处 picker（新增/编辑弹框 ×部门/标签）迁移到 v3 契约（component-lab picker-lab 范本模式）：`valueField`/`labelField` + `pickerSchema: { type: 'crud', loadAction, columns, selection: radio|checkbox, selectionOwnership: 'scope', selectionStatePath: '$_picker.selection', dataStatePath: '$_picker.rows', autoClearSelectionOnRefresh: false }`。

**编译期验证门禁（回应「为什么编译期 validation 没兜住」）**：仓库的 `validateSchema`（validate 模式，unknownBarePropertyPolicy 默认 error）此前只用于 docs 示例（schema-examples.test.ts），未覆盖 playground page-schemas。新增 `page-schemas-validation.test.ts`：对全部 40 个复杂页 JSON 逐个跑 `validateSchema` error 策略，断言 `unknown-property`（死属性类）零命中；既有的渲染器 fields 声明缺口（select:placeholder/input-number:min 等运行时有效但未声明者，约 25 文件）按 `renderer:prop` 对登记基线，**新增死属性直接红**。其余诊断码（invalid-reaction-deps 把所有无 dependsOn 的正常 crud loadAction 判 error——疑似规则过严；unvalidated-component-target 提示性；宿主 $Arr 命名空间 alias）待单独校准后再纳门。

**form-wizard 同病但未迁移**（#41 待修复）：其部门 picker 同为死属性，按同款契约迁移后暴露更深层的渲染器级问题——**真实指针点击**下内容弹框大概率不开、偶发主线程硬卡死 30s+（合成 click 稳定正常；standard-crud 同款真实点击链完全正常；dataStatePath/发布绑定/role 失焦均已隔离排除）。已回滚 form-wizard.json 避免卡死回归（维持原空白弹框现状），死属性在验证门禁基线中显式登记，待渲染器级根因（wizard valuesPath × crud 挂载/焦点 × Base UI Dialog 真实事件时序）后再迁移。

## tabs 幻影垂直滚动条修复（用户报告 dynamic-tabs，实为全部水平 tabs 全局缺陷）

### 落地内容

**问题**（docs/testing/2026/10-10.md #39）：`#/complex-pages/dynamic-tabs` tab 栏右侧出现约 30px 灰色垂直滚动条小块。目检 + 程序化排查（elementFromPoint / 逐元素 scrollHeight 扫描）确认为**全局缺陷**：master-detail、notion-database（5px 溢出滚动条完全弹出）等所有桌面端水平 tabs 均存在。根因：TabsTrigger 内建 line-variant 活动态指示条 `after:` 伪元素（`bottom-[-5px] h-0.5`，default variant 下 opacity-0 但仍占滚动区域）伸出 TabsList padding 盒约 1px（scrollHeight 33 > clientHeight 32）；渲染器水平分支只声明 `overflow-x-auto`，未声明的 y 轴按 CSS 规则计算为 `auto` → 每个 tab 栏物化出垂直滚动条，且 tab 栏上滚轮被 1px 垂直滚动劫持。

**修复**：`flux-renderers-basic/tabs.tsx` TabsList 水平分支（desktop/mobile）显式补 `overflow-y-hidden`（与 overflow-x-auto 配对，y 轴永不滚动；垂直 sidebar 列表无 overflow 类不受影响）；窄容器横向滚动契约（[G1-R6-视角8-01]）不变。

**回归守护**：包内类契约单测 ×2（水平 tablist 必含 `overflow-x-auto overflow-y-hidden` / sidebar 垂直 tablist 不含 overflow 类）；e2e cp9（complex-pages-ux-r12.spec.ts，dynamic-tabs/master-detail/notion-database 三页 tablist computed overflow-y 不得为 auto/scroll——修复前 auto 红、修复后 hidden 绿；判据用 computed overflow 而非 scrollHeight，hidden 下 scrollHeight 仍报告内容伸展不作判据）。

### 验证

- 目检：修复后 dynamic-tabs/master-detail/notion-database 三页 tablist `overflow-y: hidden`、滚动条消失（截图对照）。

## 新增审计提示词:临时方案与坏味道专项审查(docs/skills/workaround-code-smell-audit-prompt.md)

### 落地内容

- **W1-W6 判定基准**:根因可指认/出口存在/单一事实来源/触发可观测/删除可回答/语义必要。
