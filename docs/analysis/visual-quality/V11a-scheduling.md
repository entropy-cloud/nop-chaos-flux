## 0. 勘误与域定位

- **域范围**：`packages/flux-renderers-scheduling` 单包四控件（gantt / calendar / kanban / barcode-input）。diff-view 物理在 `flux-renderers-content` 包，不在 V11a owner docs（roadmap-scheduling + {gantt,kanban,calendar}/design.md）清单内，本报告不覆盖。
- **F4 表述勘误（实质定位修正）**：普查/证据卡所称「gantt **任务条**选中硬编码 `bg-blue-50`」不准确。`bg-blue-50` 实际挂在**左侧任务网格行**上（`gantt-grid.tsx:132`）；时间线任务条（`gantt-bars.tsx`）根本没有任何选中视觉——`selectedTaskId` 仅传给 `GanttGrid`（`gantt.tsx:560`），`GanttBars` 不接收该值，`gantt.css`（125 行）也没有任何 `[data-slot='gantt-bar']` 选中规则。修复面因此是「网格行 token 化（必选）+ 任务条补选中视觉（可选增强）」，见 A2。
- **Owner doc 状态失实勘误**：`docs/components/roadmap-scheduling.md` S3.2 行标 `done` 且明文「`criticalPath` 高亮关键路径红色」——代码 grep `critical` 在包 src（非测试）**零命中**，`design.md:637-650` 的关键路径契约（`calculateCriticalPath`、红色边框/2px 红顶标、底部图例）完全未实现。属普查确认的「死配置（声明无实现）」模式在 owner doc 状态区的显形，须随本 work item 勘误回写。
- **层叠结构关键事实（本域 dark 现状的解读前提）**：域内 5 个 CSS 文件（`styles.css` barrel → gantt/kanban/calendar/barcode-input 分文件，:1-4）全部无 `@layer`，经 playground `styles.css:9` 以 unlayered 方式跟在 `@import 'tailwindcss'` 之后加载；构建产物（`apps/playground/dist/assets/index-BDOsoYhj.css`）实证 Tailwind utilities 位于 `@layer utilities{...}` 内（`.bg-white` 嵌套在层内，`.nop-kanban-card` 在层外）。CSS 层叠规则：**unlayered 作者样式胜过任何 layer 内同特异性样式**。因此域内「结构色」多数实际由包 CSS 的 `var(--color-*)` 决定（dark 自适应），TSX 里的字面 Tailwind 色类中相当一部分是**被遮蔽的潜在死类**；而无包 CSS 竞争者的语义态类（选中/今日/WIP 等）则原样生效、light 锁定。darkMode 触发器已由 V1 统一为 `[data-mode="dark"]`（`tailwind-preset/src/index.ts:142`），但域内 TSX `dark:` 变体**零命中**——字面类在 dark 下不会翻转。
- **`--color-*` 令牌来源**：域内包 CSS 消费的 `var(--color-primary)` 等并非 theme-tokens 直接发布（theme-tokens 发布的是 `--primary` HSL 三元组，`theme-tokens/src/styles.css:122-330` 按 `:root[data-theme][data-mode]` 四块对称翻转），而是宿主 playground `styles.css:30-40` `@theme inline` 块的映射（`--color-primary: hsl(var(--primary))`，构建产物已实证发射）。即：包 CSS 的 dark 表现在 playground 宿主下成立，但依赖宿主发布 `--color-*` 映射层——裸 theme-tokens 宿主下这些 var 不存在（与 V6 §F2 同类宿主依赖，域内无 `canvas-styles.test.ts` 式契约测试）。
