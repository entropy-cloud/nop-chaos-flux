### 1.2 关键发现：spike-mock-leak 教训触发

**初测 5 场景中 S2/S4/S5 的 FAIL 判定为误判**，根因是 demo 配置不完整：

- ❌ 错误用法：`editor.select(rect)` API 调用 + Rect 无 `editable:true` 声明
- ✅ 正确用法：Rect 必须显式 `editable: true` + 真实点击（pointerdown→pointerup）触发选中

这是 spike plan Failure Path `spike-mock-leak` 的真实复现——**禁以 mock 推断真实 API** 纪律要求穷尽正确用法后才能下裁定。本 spike 经深度探针纠正了初测误判，避免了错误触发 R1 人工确认（否则会错误转向路径 B 自研交互层）。

### 1.3 主路径裁定（E0.1）

✅ **路径 A（leafer-editor 插件底座）在 `tree:viewport + move:drag:'auto'` 配置下成立**

证据链：

1. **深探针 P1（最严格场景）**：`tree:viewport + move:drag:'auto' + editor + editable:true + 真实点击` → Editor 完整接管拖拽，rect 移动 70×60px（150,140 → 220,200 转化为 rect.x:100→170 / rect.y:100→160），viewport 不变。
2. **深探针 P3**：去掉 `move:drag:'auto'` 后 Editor 同样工作 → **`move:drag:'auto'` 非手势仲裁阻断因素**，仅影响空白区拖拽是否触发画布平移（不影响图元拖拽）。
3. **事件流真实抽取**：`editor.select` → `tree.pointer.down` → `tree.pointer.up`（首次点击）→ `tree.pointer.down` → **`editor.move` × 9 帧** → `tree.pointer.up`（拖拽期）。事件序证明 Editor 在选中后接管 pointer 事件、连续派发 editor.move。
4. **viewport 同步正确**：拖拽期间 `app.tree.x/y` 不变，`rect.x/y` 改变 → 手势仲裁精确（图元坐标写入 + 视口矩阵零污染）。

### 1.4 适配层 cost 估计（E0.1 → E2.1 设计输入）

**适配层 cost = 极小**：

| 适配项                 | 实测结论                                                              | 实现路径                                                                       |
| ---------------------- | --------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| 图元可编辑开关         | 必须显式 `editable: true`                                             | 编辑态给目标图元加 `editable:true`，运行态关闭（双态隔离 R5 落点）             |
| 选中触发               | 真实 pointerdown→pointerup（不能用 `editor.select(target)` API 替代） | Editor 默认行为即可，无需适配                                                  |
| 拖拽写回组态模型       | Editor.move 事件派发后，rect.x/y 已写入；需监听 editor.move → 转 diff | E2.4 undo-redo 设计落点                                                        |
| move:'auto' 让位       | 空白区拖拽触发画布平移（符合 runtime 既有交互）                       | 零适配（runtime 已配）                                                         |
| move:'auto' 与框选冲突 | 空白拖拽触发画布平移而非框选                                          | **待 E0.2/E0.4 spike 复核**——若框选必须，需双态切换 move 配置或 BoxSelect 工具 |

## 选型路径建议（不裁定，仅供 E1.1 参考）

基于 E0.1 结论：**路径 A（leafer-editor 插件底座）成立**，建议 E1.1 选型 gate 采纳主路径 A。关键设计约束（输入 E2.1 编辑器架构）：

1. 图元必须显式 `editable: true`（双态切换：编辑态开 / 运行态关）
2. 选中触发必须真实点击（不能用 API select 替代完整接管）
3. 拖拽事件经 `editor.move` 派发，需在适配层监听 → 转 diff（E2.4 undo-redo 设计落点）
4. 清空选区用 `editor.cancel()` 替代 `editor.list = []`（API 漂移 #4 规避）
5. 框选 vs `move:drag:'auto'` 冲突待 E0.2/E0.4 复核
