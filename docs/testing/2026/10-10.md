## 39. 复杂页面所有水平 tab 栏出现幻影垂直滚动条（dynamic-tabs 用户报告）

- **所属组件**: tabs（flux-renderers-basic TabsRenderer + @nop-chaos/ui TabsList）
- **问题描述**: `#/complex-pages/dynamic-tabs` 页 tab 栏（概览/远程数据）右侧出现一条约 30px 的灰色垂直滚动条小块，样式突兀。排查确认为全局缺陷而非单页问题：master-detail（订单明细/操作日志）、notion-database（视图 tab 条，5px 溢出滚动条完全弹出）等所有桌面端水平 tabs 同样存在。根因：TabsTrigger 内建 line-variant 活动态指示条 `after:` 伪元素（`bottom-[-5px] h-0.5`，default variant 下 opacity-0 但仍占据滚动区域）伸出 TabsList padding 盒约 1px；渲染器对水平列表只声明了 `overflow-x-auto`，未声明的 y 轴按 CSS 规则计算为 `auto` → scrollHeight 33 > clientHeight 32 → 每个 tab 栏都物化出一条垂直滚动条（且 tab 栏上滚轮被该 1px 垂直滚动劫持）。
- **预期行为**: 水平 TabsList 只在 x 轴滚动（窄容器横向滚动契约 [G1-R6-视角8-01]），y 轴永不出现滚动条
- **发现方式**: 人工测试（用户报告）
- **状态**: 已修复——TabsRenderer 水平分支（desktop/mobile）显式补 `overflow-y-hidden`（tabs.tsx），垂直 sidebar 列表不受影响，提交 06f4a9543；判别守护：包内类契约单测 ×2（水平列表 overflow-x-auto+overflow-y-hidden / 垂直列表无 overflow 类）+ complex-pages-ux-r12.spec.ts "cp9-tabs-y-overflow"（dynamic-tabs/master-detail/notion-database 三页 tablist computed overflow-y 不得为 auto/scroll，修复前红、修复后绿）

## 41. form-wizard 部门 picker：v3 内容弹框在真实指针点击下不稳定（偶发主线程卡死 30s+）

- **所属组件**: picker × wizard（flux-renderers-layout）交互组合
- **问题描述**: #40 排查中发现 form-wizard 步骤二的部门 picker 同为旧 API 死属性（弹框空白）。按 #40 同款 v3 契约迁移后出现更深层问题：**真实指针点击**触发器时弹框大概率不开（aria-expanded 停留 false）或页面主线程硬卡死 30 秒以上（evaluate/输入全部无响应，随后可自行恢复）；合成 click（el.click()）则稳定打开且行数据正常。同款 pickerSchema 在 standard-crud 弹框与 component-lab 下真实点击均正常。已隔离的因素：`dataStatePath` 发布、selectionOwnership/StatePath 绑定、role 失焦验证——去掉后问题依旧；触发条件收敛为「wizard 上下文 + picker 弹框携带 crud 内容 + 真实指针事件」。怀疑方向：wizard `valuesPath` 发布链 × crud 挂载/焦点管理 × Base UI Dialog 初始焦点扫描在真实事件时序下的交互（合成事件不移动焦点故不触发）。
- **预期行为**: 真实点击稳定打开带内容的弹框并可正常选择
- **发现方式**: 人工测试（#40 修复验证中发现）
- **状态**: 已修复（2026-10-11）——渲染器级根因为 **reaction 空 dependsOn fail-open 死循环**：crud loadAction 未声明 `dependsOn` 时 `createRootDependencySet` 返回 `undefined`，`scopeChangeHitsDependencies(change, undefined)` 恒 true → 订阅链上任何 scope 变更（包括步骤表单 `valuesPath` 对 `wizardData.step2` 的发布，每次新对象身份）都响应式重触发 fetch → onSettle 写 `$_picker.rows`（新数组身份）进 form values → valuesPath 再发布 → 循环；picker 内容 region 无 slot 参数不建独立 fragment scope，crud 直接落在表单 scope，循环得以闭合。真实/合成点击只是进入循环的时序变量（fetch 与 force 竞态决定能否自愈）。诊断靠 CDP `Debugger.pause()` 在卡死中连采现场栈（`Profiler.stop` 会排在堵死的主线程后面取不到）。修复：`createRendererReactionHandle` 空 dependsOn 改 fail-closed（不做反应式触发；命令式 dispatch/force/crud 自身 state 驱动的重载不受影响），提交见当日 dev log；详见 docs/bugs/169。form-wizard.json 已按 #40 同款 v3 契约完成迁移；判别守护 e2e（真实点击→行渲染→选择→确认→回写）已挂在 complex-pages-interaction-state.spec.ts，page-schemas 验证门禁的 wizard picker 死属性基线同步收缩
