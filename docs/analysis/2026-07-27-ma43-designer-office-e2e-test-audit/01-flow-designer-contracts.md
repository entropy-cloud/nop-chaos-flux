### 3.4 Duplicate / Consolidation Observations

- **core.test.ts** and ****tests**/core-graph.test.ts** are ~90% identical tests. Unique content in core-graph: `replaceDocumentFromHost`, `selectBranch`, nested transaction commit. These could be consolidated.
- **designer-page.tree.test.tsx** and **designer-page.tree-history.test.tsx** share setup patterns but test distinct behaviors.

### 3.5 Key Strengths

- **Tree projection**: Exceptionally well tested with 3 domain-specific suites covering chains, branches, merges, nesting, data preservation, edge type resolution, and ELK layout integration.
- **Core error fidelity**: Hook error propagation through events thoroughly tested for beforeCreateNode, beforeConnect, and beforeDelete.
- **UI state**: Palette/inspector collapse, viewport, multi-node operations with idempotence and independence checks.
- **Command adapter**: Both graph mode and tree mode command routing well covered including edge cases (duplicate-edge rejection, port preservation, transaction rollback).
- **Action provider**: Method mapping, payload validation against manifest contract, ActionResult-shaped cause propagation, structured error results.
- **Manifest projection**: `buildDesignerScopeData` alignment test cross-references scope data shape with manifest projection schema - rigorous contract enforcement.
