## Goals

- 7 条 P1 在 live code 上全部收敛，且每条配一条能抓住回归的 focused proof（行为类）或静态/可观测检查（机械类）。

## Failure Paths

| 场景                        | 触发                                                                   | 预期行为                                                                            | 可重试                 | 用户可见表现                                                |
| --------------------------- | ---------------------------------------------------------------------- | ----------------------------------------------------------------------------------- | ---------------------- | ----------------------------------------------------------- |
| FP-1 hover 候选             | 鼠标移过 suggestion popup 项                                           | **不**触发提交，仅高亮该项（activeIndex 更新）                                      | 否                     | 候选常驻可点选；不再 hover 即插入                           |
| FP-2 持焦 Enter 提交        | Tiptap 持焦时按 Enter 提交（`clearOnSubmit:true` 默认）                | 提交成功 + 编辑器内容清空                                                           | 否                     | 发送后输入框为空，可继续输入下一条                          |
| FP-3 流式中重发编辑         | 流式进行中点铅笔编辑后重发                                             | `resubmit` 被 `isProcessing` 守卫拦截，编辑器保持打开                               | 否（等流式结束可重试） | 不静默丢字；按钮禁用或保留编辑态                            |
| FP-4 create/rename 存储失败 | `storage.saveConversation` reject                                      | 经 `reportStorageError({phase:'saveConversation'})` 回调 host                       | host 决定              | host 可 toast/重试；内存列表与存储分歧可被 host 观测        |
| FP-5 快速切换会话           | A→B 快速切换且 A 的 loadMessages 慢                                    | A 的迟到 resolve 被 version guard 丢弃，`activeEngine` 不被错换，`engineB` 不被误删 | 否                     | 始终展示当前 activeId 的会话；无 ghost 引擎                 |
| FP-6 connector 缺失发送     | `ai:send`/`component:sendMessage` 在 `connector=null` 的外部引擎上触发 | `draft.lastError` 写入结构化 "connector-missing" 错误                               | host 决定              | host 收到结构化 error cause，可区分「未配置」与「请求失败」 |

## Test Strategy

本档选择：**建议有测**

理由：7 条均为已确认 live defect / contract drift（非鉴权、非对外公共 API 契约变更），但多条命中「绿测藏雷」家族——上一轮自评盲区明确点名 rich-text 子路径的「测试名承诺的路径恰好是断言没走的那条」。因此每个行为类 Fix 必须配一条能真正走通被修复路径的 focused regression proof（hover、持焦提交、isProcessing 守卫、storage reject、快速切换、connector-missing），P1-4 机械项用 grep/static 断言。
