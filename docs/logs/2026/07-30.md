## Docs Fix: `closeSurface` 不应放在 `onSubmitSuccess` 中

### 问题

flux-guide 和 architecture 文档中多处推荐 `"onSubmitSuccess": [{ "action": "closeSurface" }, { "action": "refreshNearest" }]` 的写法。这个模式在职责划分上不正确：

- `onSubmitSuccess` 是 owner 侧的数据回调（刷新、导航、上报），不是 UI 控制点
- `closeSurface` 是 UI 动作，应作为 `submitForm` 的后置操作（`then` 链）
- 把 `closeSurface` 放在 `onSubmitSuccess` 中导致关闭与刷新的时序耦合，且与 `submitForm.then` 链重复

## Bug Fix: `refreshNearest` 找不到 CRUD — 两层根因

### 问题

dialog form submit → `onSubmitSuccess` → `refreshNearest` 无法找到 CRUD 组件，导致创建/编辑后列表不刷新。e2e auth 测试 27✓/7✗。

### 根因 1: form 生命周期处理器缺少 `componentRegistry`

`form.tsx` 中 `submitAction`/`onSubmitSuccess`/`onSubmitError`/`onValidateError` 四个生命周期处理器在 dispatch action 时没有传入 `componentRegistry`。这些处理器在 React render cycle 外执行（由 `form.submit()` 触发），无法从 React context 获取。

**修复**: 在所有四个处理器的 context override 中添加 `componentRegistry: currentComponentRegistry`，并在 `useEffect` 依赖数组中添加 `currentComponentRegistry`。

### 根因 2: CRUD handle 缺少 `scope` 属性

`useCrudHandle` 注册的 component handle 对象没有 `scope` 字段。`component-handle-registry.ts` 的 `indexHandle` 只在 `handle.scope` 存在时才将 handle 按 `scope.id` 索引到 `handlesByScopeId`。因此 `findFirstInScope` 永远找不到 CRUD handle，`refreshNearest` 返回 no-op。

**修复**: 在 `useCrudHandle` 中添加 `scope: nodeScope`（`props.node.scope`）到 handle 对象，并添加到 `useEffect` 依赖数组。

### 验证

- `dialog-form-submit-refresh-crud.test.tsx` 通过（CRUD 在 form submit 后重新加载）
- e2e auth 测试从 27✓/7✗ 提升到 **34✓/5✗**
- 剩余 5 个失败为不同根因（edit/view/delete 各有独立问题），不再与 `refreshNearest` 相关
