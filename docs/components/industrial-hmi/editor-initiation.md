## 1. 立项背景与范围裁定

- **范围裁定在案**：讨论文件 §七 Q8（"选中/拖拽等编辑器交互本期不做"）+ §八 决策 1（"运行时渲染优先，编辑器后置为后继 mission，roadmap 末尾预留 I16 立项入口，不实现"）+ roadmap I16.1（"编辑器调研与立项材料：图元拖拽放置/属性面板 schema/连线/undo-redo/画布工具箱/与 runtime 共享引擎层复用点 → 产出后继 mission 建议文档"）+ gate-4-review §10（"编辑器后继 mission 立项（复用点：sky 交互覆盖物/图元注册表/组态 JSON 序列化/component:\* 句柄扩展）；本 gate 无新增编辑器范围项"）。**本材料不引入任何新编辑器范围项。**
- **运行时基线（I0–I15 已收口）**：`scada-canvas` renderer 全链落地——24 内置符号、点表三源、组件句柄面 9 方法、事件全链路（click/dblclick/hover + `createNormalizedActionEvent` + helpers.dispatch）、sky 交互覆盖物（InteractionOverlay，points 包围盒兜底）、测试句柄 `window.__flux_scada_<cid>` 恒开、benchmark 全项达标（首屏 373.1ms / 指针拖动 rAF best 70.3fps / 内存 130.6·127.8MB / 1 万点刷新 41.9ms，benchmark-report.md）。
- **本材料性质**：立项材料 = 编辑器功能范围与优先级 + runtime 复用点三态清单（live 核对）+ 技术选型考量 + 工作量与里程碑评估 + 风险清单与人工确认项预标记。**不实现编辑器、不引入依赖、不改 runtime 代码、不产出可执行 plan**（Non-Goals 与 plan `2026-08-04-0902-2` 一致）。
- **编辑器工作量定性**：讨论 Q1 说明编辑器工程量为运行时 3–5 倍——本材料据此给出档位化工作量评估（§5），具体数字由后继 mission spike 与编排后校准。

### 4.2 两路径对比与考量

| 维度                 | 路径 A：leafer-editor 插件底座                                                                                                                                                             | 路径 B：自研交互层（挂 sky）                                            |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------- |
| 交互原语             | 现成（TransformTool/EditBox/EditSelect/成组/层级/事件族，§4.1 能力边界）                                                                                                                   | 全量自建（拖拽/多选/手柄/参考线/对齐）——工程量最大头                    |
| 组态语义适配         | **需适配**：插件操作 leafer 节点，需写回组态模型（节点↔`ScadaSymbolNode` 双向同步 + 属性面板联动 + undo diff 捕获）——适配层是本路径的实质工作量                                            | 天然直接操作组态模型（交互直接产出 diff），无双向同步面                 |
| 与 viewport 插件共存 | 官方 partner 共装 + zoomLayer 交互证据（§4.1 轻量核证③），**但"tree: {type:'viewport'} 下 Editor 拖拽 vs 画布平移手势仲裁"未实测**——`drag:'auto'` 让位语义与 Editor 拖拽的交互优先级待验证 | 手势仲裁自定（编辑工具状态机显式区分"拖动图元/平移画布"），无外部仲裁面 |

### 4.3 选型裁定（立项粒度）

- **主路径：路径 A 优先评估（leafer-editor 插件底座 + 组态语义适配层自研）**——交互原语现成、叠加层模型与 runtime 既有预留一致（design-engine.md §6:179 + §12.3 后续阶段 I16 行 :282-290 + research-summary E12）；组态语义适配层（属性面板 schema/undo-diff/连线声明/保存加载）无论哪条路径都必须自研，是编辑器价值核心，不因选型改变。
- **否决条件（触发路径 B + 人工确认）**：后继 spike 若验证 "viewport 插件共存手势仲裁" 不成立（Editor 拖拽与画布平移冲突不可调和）或 Editor 插件 API 漂移面过大（适配成本 ≥ 自研交互原语成本）→ 转路径 B（自研交互层挂 sky，复用 InteractionOverlay 模式 + 引擎命令面）。
- **待后继 spike 验证项（Failure Paths `selection-evidence-gap`：缺证据项显式标注，不臆断）**：
  1. `tree: {type:'viewport'}` + `@leafer-in/editor` 共存的挂载形态与手势仲裁（拖拽图元 vs 平移画布）——**决定选型主路径成立与否**；
  2. Editor 事件族（EditorMoveEvent/EditorScaleEvent/EditorRotateEvent 等载荷形状，render-engines §5 :122 全名）与引擎事件桥的衔接（gate-3 M-1 类载荷面核对）——**决定适配层成本**；
  3. 编辑态覆盖物密集场景性能（多选手柄/参考线在 10 万图元组态上的交互帧率）——**决定编辑态包络**（§5.2）。
- **mock↔真实教训的落地要求（写入后继 mission 约束，本材料记录）**：编辑器交互层的一切交互 API 设计必须先在真实 leafer 上 spike 固化（对齐 gate-3 §3 抽查口径与 docs/bugs/76 先例）；**禁止以 mock 行为推断真实 API**；交互层的测试策略沿用"真实浏览器 e2e 程序化断言 + 测试句柄"（roadmap 测试纪律）。

## 5. 工作量与里程碑评估

### 5.1 工作量档位

> 定性档位（编辑器工程量为运行时 3–5 倍，讨论 Q1）。**基准定义：本文「单期」= 运行时实现域 I4–I15（8 个实现 work item）这一整期**，不是单个 work item——避免口径双读。以下为**立项粒度档位估计**，具体排期由后继 mission 编排确定，M1 前须经 spike 校准（§4.3 待验证项）；三里程碑合计约 4–6 倍，略高于 Q1 口径档（3–5 倍）——差异为工程量评估的不确定带，校准后收敛。

### 5.2 benchmark 包络对编辑器的适用性说明（人工确认项预标记依据）

- **运行态包络不变**：benchmark 验收包络（10 万图元 ≥45fps / 首屏 <2s / 内存 ≤320MB / 1 万点刷新 <200ms，roadmap 总览）是运行时红线，编辑器引入的覆盖物/手柄**不得在运行态启用**（编辑态开关隔离，design-engine.md §6 覆盖物最小化口径）。
- **编辑态包络需另立**：编辑态交互性能目标（拖拽响应帧率、属性面板刷新延迟）与运行态包络解耦——建议编辑态档位（如拖拽 ≥30fps、编辑操作响应 <100ms）由后继 mission 在 M1 spike 阶段裁定并**标记人工确认**（新包络数字属 benchmark 验收阈值类变更，roadmap Cross-Cutting「人工确认阈值」条款覆盖"benchmark 不达标"的对应面，新立编辑态包络应显式确认）。
- **共享引擎的复合约束**：编辑-运行同帧场景（编辑态预览 1 万点刷新）仍受运行态红线约束（合帧 + 脏属性收集 + 禁逐点直刷），编辑器不得绕行。
