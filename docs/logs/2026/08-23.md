### 根因

`packages/flux-compiler/src/schema-compiler/shape-validation-node-fields.ts:39-66` 的 `validateKnownPropValue`：

```ts
function validateKnownPropValue(schema, renderer, key, ...) {
  const contract = renderer.propContracts?.[key];
  if (!contract) {
    return;   // ← 早退：没 contract 就不查
  }
  // 用 contract.shape 调 validateFluxValueShape
}
```

校验能力**已实现**（`flux-value-shape-validation.ts:152-339` 支持 literal / union / boolean / string / number / record / array / object / schema-definition / unknown），但 14 个 renderer 包里 9 个的 `propContracts` 覆盖率 ≤ 47.2%，其中 AI / mobile / scheduling **0%**。结果是 enum 错值（如 `flex.direction: "col"`）一路放到 runtime，runtime 通过 `Record<K, string>` 索引或 if-else 静默退化，从不报错。

### 关键学习

1. **`hasClosedPropModel` 的副作用**（`shape-validation-utils.ts:21-26`）：任何 propContracts 自动让 renderer 进入 closed model，`unknown-property` 检查立即生效——`data-*` 必须显式豁免（line 245 处的 `!key.startsWith('data-')`）。
2. **shared formFieldRules 的共享 contract 模式**（form 包 11 个 input renderer 共享同一份 `formFieldRules: SchemaFieldRule[]`）：照搬 `validate: validatePropContract` 的旁路思路，新增 `formFieldContracts: Record<string, RendererPropContract>`，单源真相但**编译器不强制**（人工维护）。
3. **runtime fallback 与 compile-time validation 的语义分层**：runtime 的 `Record<K, string>` 索引或 `if-else` 兜底仍然存在（处理"绕过 schema 构造的极端路径"），但所有正常 schema 路径都被 propContract 拦截；测试这种 runtime fallback 改用直接 unit test（`resolveIconSize('xl')`），不通过 schema 渲染。
