- Plan：`docs/plans/463-threejs-i0-research-plan.md`（draft review 2 轮由独立子 agent 完成，pass-with-minors 后升 active）。

- 关键发现（I1.1 输入）：
  - 设计 v4 `formulaCompiler.compileExpression()` 产物喂 `evaluateWithState` 类型不匹配（`CompiledExpression` ≠ `DynamicRuntimeValue`）；scada 实际走 `compileValue()`/`evaluateValue()`。
  - three 0.186 `GLTFLoader.loadAsync(url, onProgress)` 仅 2 参，v4 的 AbortSignal 第 4 参不存在；取消需 generation-guard。
  - 路线图「复用 scada socket 数据桥接」勘误：industrial 包内零 `openSocket` 调用；契约在 `flux-core/src/types/renderer-api.ts:136-167`，host 实现在 `apps/playground/src/env/socket-impl.ts`。
  - v4 events 注册为 `kind: 'prop'` 的理由（"compiler 约束"）未指明出处；平台标准是 `kind: 'event'` → `props.events`。
- 基准框架：`scripts/three-perf/bench-scene-graph.mjs`（7 场景，`--json` 支持），基线：位置写入 ~5.4ns、颜色写入 ~185ns、场景组装 ~60µs——绑定热路径 CPU 段对 16ms 帧预算余量充足。根 devDeps 增 `three@0.186.0` + `@types/three@0.186.0`。
- 环境修复（非本计划改动引入）：本工作区首次 `pnpm install` 后 `pnpm typecheck` 因 `tsconfig.base.json` paths 缺 `flux-renderers-form-advanced` 映射而失败（fresh checkout 无 dist 时暴露，预存在债务，仅 build-first 可绕过）；`pnpm lint` 因分支落后 origin/master 缺 4 个 i18n key 而红——已 merge origin/master（解决 package.json turbo 版本冲突，保留 three 依赖），两门禁恢复绿。tsconfig paths 缺口未修（跨包契约变更，另行处理）。
- 验证（merge origin/master 后）：`pnpm typecheck` 39/39、`pnpm build` 39/39、`pnpm lint` 39/39、`pnpm test` 72/72 任务（38 包报告测试计数，**12,185 passed / 0 failed**）、`pnpm check` exit 0（仅注册豁免）、bench 脚本跑通且 `--json` 可解析。
