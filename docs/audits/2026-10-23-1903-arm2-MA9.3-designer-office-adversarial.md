## 1. Findings（新形状 4 + watch 升格证据 1；在案复现另列 §4）

### P1-MA9.3-001 · taskflow 导入不校验 kind：wrong-kind DSL「成功」清空工作文档 — **新案（执行者 live 复核成立）**

- **What**：`{"kind":"not-taskflow","steps":[]}` 经导入对话框确认 → toast「导入成功：0 个节点」，设计器文档被替换为空投影（实测节点 7 → 0）。parser 仅检查 `steps` 是否数组（`apps/playground/src/taskflow-designer-lib/dsl.ts:107`），`kind` 全程无校验——wrong-kind 是 6 个无效输入 case 中唯一被接受的（empty/not-json/steps-not-array/null-body/array-body 全部正确拒绝，判别面干净）。
- **证据**：`probes/log-tf2.txt`（before=7 after=0 + toast 原文）；**执行者复核**（`executor-verify.spec.ts` V1，19:0x 实跑）：`wrong-kind toast=导入成功：0 个节点 before=7 after=0`——独立复跑同读数；源码亲读 dsl.ts:103-113 坐实。
- **定级 P1**：导入通道的静默破坏性数据丢失（会话内），触发成本极低（粘贴任意含 `steps:[]` 的 JSON）。**不走 P0 通道依据**：需用户显式打开导入对话框并确认（非隐式损坏），与在案 IS-taskflow-designer-010 同面同级先例一致。
- **fix direction**：`parseNopTaskDSL` 校验 `kind === 'nop-taskflow'`（+ `task` 形状）；拒绝路径复用现有「导入失败」toast；kind 白名单回归守护随修。

### P1-MA9.3-002 · word 编辑器深栈 undo 内容回退失真：undo×15 后输入段残留 + 按钮态失真 — **新案（执行者复核机制收窄）**

- **What**：canvas 编辑器连续输入 15 段后 toolbar 撤销 ×15，**内容不完整回退**：Round B 读数 4/4 抽样段全部存活、redo×15 不还原（undo→redo 往返不守恒）；执行者复核轮 3/4 抽样段存活（仅最早 1 段被移除）。undo 按钮全程 enabled——**栈态宣称有条目而内容不回退**（按钮可点、内容不动、无任何用户可见提示）。同会话**单步 undo 正常**（ASCII/CJK 各自 type→undo×1 均精确移除，执行者复核实证）。
- **执行者对账勘正**：Round B 初判「undo 与文档状态完全脱钩」（undo×15 零内容变化 + 字数计 212→257 漂移）；执行者 live 复核（V2：poll 读数修正后）证明**单步 undo 通道健康**、深栈场景部分回退——机制声称收窄为「深栈/长输入会话下 undo 栈与文档内容部分脱钩」；Round B 的 257 计数漂移未在复核轮复现（计数 UI debounce 读数伪影候选，§5-R13 备案），**内容级红维持**。P1 定级不变。
- **证据**：`probes/log-we2.txt`（P-UR-we-1：undo 轨迹 257 恒定 / preview 含段14号=true）；执行者复核 `executor-verify.spec.ts` V2：`ASCII typed-in=true undo-removed=true`、`CJK typed-in=true undo-removed=true`、`深栈 undo×15 后 4 个抽样段存活=3/4`。

### P3-MA9.3-005 · xui:sid 剥离越权：非 schema 载荷用户键静默删除 — **新案（带保留命名空间抗辩；源码坐实）**

- **What**：`stripSessionIds` 对任意 plain object 无差别剥离 `xui:sid`（`round-trip.ts:116-129`，执行者亲读坐实：`if (key === SESSION_ID_KEY) continue` 对递归全对象生效），而注入仅对 schema 节点（:90-105）——用户数据中自带 `xui:sid` 键经导入→导出一轮即静默丢失（浅层+嵌套双实证）；INV-A 对该类文档不成立；`collectSessionIds` 一并误收。

## 10. 总评

- **undo/redo 是 designer+office 族对抗姿态下最脆弱的面**：flow（P0-002 修复后）全绿健康，word 深栈失真（P1-002）、report-host 双栈时间旅行（在案深化）、spreadsheet 焦点链 undo 不可达（在案升格）、taskflow 导入清史——与 git 热点「undo 语义三次易手」互证：历史栈语义缺乏统一的「栈态-内容态」一致性契约。
- **序列化往返恒等式本体成立、破口在入口**：flow byte 级往返、spreadsheet 幂等、page 2000 节点守恒、协作命令 7 kind 恒等全绿；全部红点位于**通道入口**（taskflow kind 不校验、`xui:sid` 保留命名空间双向破例）——入口校验是本族序列化面的系统性薄弱层。
- **长会话面整体健康**：flow 画布 400 op 零累积退化（MA9.1 gantt 机理未跨包复现——线索关闭）、spreadsheet/word 输入时延无劣化、堆面全平；唯一长会话缺口是树回写 LRU 有界记忆盲区（P2-004，单点修复路径明确）。
- P1 ×2 均属「用户一次动作触发的内容丢失/失真」类——修复合并建议：kind 校验（1 行级）+ word undo 栈快照链核查 + inspector 提交链修复，三者皆可在 MR3 单批收口。
