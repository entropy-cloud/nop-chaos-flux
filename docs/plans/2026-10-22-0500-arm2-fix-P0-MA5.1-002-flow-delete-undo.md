## Purpose

修复工作流宿主 `deleteSelection` 删除后撤销不可达的断点，使键盘删除可撤销；同时消除与 IS-flow-designer-010（工具栏恒 disabled）的叠加（本 plan 仅修 002；010 归 MR 行）。

## Current Baseline

- 候选链路（Round A 定位 + draft review M1 勘正锚点）：**graph 路径 `designer-command-adapter.ts:62`** `beginTransaction('delete-selection')`（工作流 tab 走 graph 路径、含边删除；**:180 tree / :162 case 标签为正常对照组**——taskflow 可撤销即证）→ `core.ts:545` `commitTransaction` → :560-561 仅 `result.shouldPushHistory` 时 `pushHistory()`；`shouldPushHistory = nextStack.length === 0`（transactions.ts:53）。
- **Phase 1 取证勘误（2026-10-22，Outdated Note）**：上述事务→入账链路经隔离探针 + 组件探针证实**全程健康**（删除后 `canUndo===true`、事件序 `transactionStarted→…→historyChanged canUndo=true→transactionCommitted`）。真实断点在**键盘撤销的可达性**：工作流节点卡片可聚焦（`designer-xyflow-node.tsx:303-315` `role="button" tabIndex={0}`），点击选中的同时 DOM 焦点落在卡片上；Delete 触发 `deleteSelection`（经 adapter 事务，正常入账）后**卡片被卸载，浏览器把焦点回落 `document.body`**，紧随的 undo/redo keydown target=body 在 `use-designer-shortcuts.ts:41` `isInsideDesigner` 门被整体拦截——删除因此"事实上不可撤销"。既有 e2e `flow-designer-undo-clipboard.spec.ts:14` 以显式 `.fd-xyflow-surface.focus()` 重聚焦掩盖了该分叉（真实用户不会手动重聚焦）；taskflow 对照可撤销源于其工具栏 undo 无 disabled 表达式（schema 对比 `taskflow-workflow-schema.json` vs `workflow-designer-schema.json`）。工具栏 undoDisabled=true 一支为 010 假阴性，不在本 plan 内。
