> **数值说明**：下表 LeaferJS 性能数字为**官方自报**（联网检索存在转述出入，如内存 320MB vs 350MB），待 mission I0 阶段逐数字标注来源并校准后才作为设计依据。

### 候选底层渲染引擎

| 候选                      | 协议 | 特点                                                                                                                                                                                                                                                                                                                                  | 与工业组态的匹配度                                                   |
| ------------------------- | ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| **LeaferJS**（leafer-ui） | MIT  | Canvas 2D 场景图，百万图形（官方基准：100 万矩形首屏 1.28s / 320MB / 拖动 60fps），70KB min+gzip、零依赖、类 DOM API、内置 Editor 插件（缩放/旋转/多选）、Flex 布局、跨平台（Web/Node/小程序）；官方场景明列「万级节点电力组态」；仓库族：`leafer`（核心）、`leafer-ui`、`leafer-in`（官方插件）、`leafer-editor`、`LeaferJS`（集成） | 高 —— 性能天花板高，但组态语义层（数据绑定/动画/点表）需自研         |
| **Meta2d.js**（乐吾乐）   | MIT  | TS 写的实时数据交互 2D 引擎，1.2k star；专门面向 Web SCADA/IoT/数字孪生；data-driven view、订阅消息、1000+ 动画、生命周期 hooks、视频播放、可扩展；有在线编辑器（2ds.le5le.com）与 ThingsBoard designer 案例                                                                                                                          | 高 —— 组态语义开箱即用，但自研引擎、社区规模小、定制深、文档中文为主 |
| **Konva.js**              | MIT  | 成熟通用的 Canvas 场景图库，react-konva 生态，TS 支持好，性能中等                                                                                                                                                                                                                                                                     | 中 —— 稳定可靠，但性能/图元生态需自建                                |
| **Fabric.js**             | MIT  | SVG 导入导出强、对象模型完整，性能偏弱                                                                                                                                                                                                                                                                                                | 中低 —— 偏图形编辑器场景                                             |
| 自研 Canvas 引擎          | —    | 控制力最强、无依赖风险                                                                                                                                                                                                                                                                                                                | 低 —— 成本最高，违背"复用第三方"要求                                 |

### 候选组态应用/平台（供设计提取）

- **FUXA**：完整开源 SCADA/HMI/Dashboard 平台（Node 后端 + Web 前端），行业实际使用，适合提取「点表/变量绑定、报警、趋势」设计。
- **SceneV**：Vue3+TS+Canvas/WebGL 低代码组态引擎，图元拖拽/属性面板/事件体系完整。
- **Sovit2D / 智雨物联**、**vue-webtopo-svgeditor**（SVG 方案）、**OSHMI**（老牌 SCADA）、**mxGraph/maxGraph**（流程图/拓扑）等，作为补充参考。

### 通用引擎层设计要点（初步提炼）

1. 场景图（scene graph）+ 脏区/局部重绘；图层分层（背景/图元/交互/HTML 覆盖层）。
2. 坐标变换：世界坐标 ↔ 视口坐标，缩放/平移/旋转。
3. 数据绑定层：点表/变量表 → 图元属性 → 动画 → 事件，支持订阅与节流刷新。
4. 状态驱动动画（多状态呈现：运行/停止/故障/闪烁/流动/旋转）。
5. 命中检测与交互（拖拽、缩放、旋转、多选、事件冒泡）。
6. 图元注册机制（类似 flux renderer registry 的 `registerScadaSymbol`）。
7. 组态 JSON 序列化/反序列化（schema ↔ 场景图），供 flux schema 内嵌。
8. React 桥接：命令式引擎 + React 声明式 props（ref/effect 同步），遵循 `RendererComponentProps` 契约。

## 八、最终决策（mission 立项要点）

1. **范围**：运行时渲染优先（引擎 + 图元库 + 数据驱动 + 画面渲染）；编辑器后置为后继 mission（roadmap 末尾预留 I16 立项入口，不实现）。
2. **选型**：LeaferJS（leafer-ui）为底层渲染底座（MIT、百万图形、70KB、Editor 插件），组态语义层全部自研——与"业内最高水平 + 复用第三方"目标一致。
3. **数据模型**：双轨——组态内点表（自包含）+ flux 表达式桥接。
4. **组件形态**：单 renderer type `scada-canvas`，props 内嵌组态 JSON。
5. **测试**：纯逻辑层 Vitest 单测 + Playwright e2e 程序化断言；Benchmark 对标官方基准档。
6. **回顾机制**：roadmap 固定 4 个 review gate（I1/I3/I7/I12），每次由独立 agent 对照上游产物审查，可修正方向。
7. **调研下载**：`~/sources/industrial-hmi-research/` 目录，6 组代表项目全量 clone + 浅调研补充项目。
8. **产物**：

## 九、总结

### 最终需求

为 `nop-chaos-flux` 新增工业组态（HMI/SCADA）**运行时渲染**能力：高性能 Canvas 场景图引擎（LeaferJS 底座 + 自研组态语义层）+ 工业图元库 + 实时数据驱动 + 画面渲染组件，达到对标 LeaferJS 官方性能档（数值官方自报，待 I0 调研校准）的业内高水平（复用第三方渲染底座、语义层自研）。

### 关键决策（含选项依据）
