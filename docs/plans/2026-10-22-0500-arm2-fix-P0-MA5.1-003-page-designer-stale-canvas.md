> Last Reviewed: 2026-10-22
> Source: MA5.1（plan 690）Round B `IS-page-designer-015`（执行者 b03/b08 探针复证：label 改「确认提交」后大纲树/导出 JSON 已更新、画布 anchorText 恒 "Button"（blur+1.5s/重选均不变），切预览显示新值、切回编辑整树重挂后恢复；importDocument 同形替换同样不刷新）

## Purpose

修复设计器文档 `updateProps`/`importDocument` 同位重建时画布节点不随重编译模板刷新的缺陷，使"改了=看得见"的核心编辑回路成立。

## Current Baseline

- 候选链路（Round B 定位，未逐层证实）：设计器文档不带 `schema.id`，edit-assembly 仅投影 sid→testid（`packages/page-designer-renderers/src/.../edit-assembly.ts:30-32`）→ `createNodeId` 回退 path（`packages/flux-core/src/utils/schema.ts:34-40`）→ 同位重建 templateNode id/React key 不变 → 挂载期注册的 per-node 运行时状态（`node-renderer-resolved.tsx:81-135` 一带 propsProgram 注册）不随重编译刷新；`key={mode}` 整树重挂即恢复。
- 本缺陷可能是 flux-react 通用契约问题（"同 id 节点 props 重编译后是否重注册"）而非仅设计器——Phase 1 取证须判定归属（flux-react 核心 vs 设计器 id 方案）。

## Goals

- 判别测试：渲染真实 page-designer（或最小 SchemaRenderer 复现：同 path id 节点、重编译模板改 props）→ 断言 DOM 文本=新值；旧实现必红。
- live 探针 b08 形态转正：label 编辑后画布文本=新值（无需模式切换）。

## Non-Goals

- 不改设计器 id 方案之外的序列化格式；不修 016（同族，随本修复复测，若自动修复则在 MR 行记 delegated）。
