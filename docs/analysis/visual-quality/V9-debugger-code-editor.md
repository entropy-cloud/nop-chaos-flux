## 1. Findings 逐项核实

### F1 debugger 注入式 CSS 不接设计令牌（成立，且比证据卡更深一层）

- **结构与注入机制**：全部样式为单文件模板字符串 `DEBUGGER_STYLES`（`panel/styles-css.ts:3-506`）+ `DEBUGGER_STYLE_ID = 'nop-debugger-styles'`（:1）。注入器 `useInjectDebuggerStyles(enabled)`（`panel/styles.ts:6-20`）：`document.createElement('style')` + `document.head.appendChild`，按 id 查重幂等（:12-18）；由 `panel.tsx:191` 以 `chrome.enabled` 触发。**运行时字符串注入 = 不进任何包 CSS 构建管线、不经 Tailwind `@source` 扫描、不随主题文件分发**——这是令牌化方案面的第一约束（改造必须在字符串内完成，不能假设构建期处理）。
- **令牌消费面（fallback-only）**：`var(--nop-debugger-*)` 消费 **71 处、涉及 42 个不同令牌名**（grep 精确清点）；全仓（packages + apps，含 playground 宿主样式）**零定义**——fallback 永远生效，令牌通道目前是"可被宿主覆盖的钩子"而非实际令牌化。42 个令牌构成：bg/border/shadow/text 四基色（:13-20）+ eyebrow :55 + card/chip/detail/highlight 容器族（:83-85/:144-145/:185/:190/:203/:261-262/:274）+ badge 6 组 ×2（:217-222）+ json 4 色（:297-300）+ muted-text/detail-text（:165/:190）+ launcher 4（:307-308/:313）+ overlay 5（:334-335/:339）。fallback 全部为暗色 rgba/hex（如 `--nop-debugger-bg` 深蓝黑双层渐变 :15-16、`--nop-debugger-text` #eef4fb :20、`--nop-debugger-eyebrow` #ffcf8b :55）。
- **裸值面（连 var() 通道都不走，18 处）**：8 处裸 hex——:225 data-slow 琥珀字、:319-321 三个 status 色（#ffd18a/#9df3ca/#ffadad）、:406 icon-button active 蓝字、:425 tooltip 白字、:446/:478 检视面板蓝字；10 处裸 rgba——:225 data-slow 底、:346 resize-handle、:392 minimized badge、:396 error badge、:405 icon-button active 底、:424 tooltip 底、:434 tooltip 箭头、:444-445 inspect-hint 底+边、:477 inspect-tag 底。另 `--nop-debugger-bg` 渐变 fallback 本体（:15-16）是跨行 var() 内值，计数时易漏（属 fallback 面非裸值面）。
- **亮色宿主问题的机制（比"突兀"更具体）**：面板根/launcher/minimized 三种根节点都挂 `nop-theme-root` 类（`panel.tsx:309/:340/:365`），且面板内部直接使用 `@nop-chaos/ui` 的 `Button/Tabs/TabsList/TabsTrigger`（`panel.tsx:4`，icon-button 实例 :375-428，Tabs :432-443）——shadcn 件消费的语义变量随宿主主题翻转，而注入 CSS 的卡片/chip/badge/输入框经 fallback **强制暗色**：亮色宿主下同一面板内两套色彩体系混色。普查 :104「色板全暗色 rgba fallback，亮色宿主下突兀」定性成立。
- **契约测试锁定现状**：`panel/styles.test.ts:5-9` 把 fallback 模式写死进断言（:7 `toContain('background: var(')`、:8 `toContain('var(--nop-debugger-text, #eef4fb)')`）；:11-17 锚定选择器作用域——令牌化必须同步改写 :7-8（架构同 V6 的 `canvas-styles.test.ts` 宿主发布默认值契约）。
- **可行性面**：theme-tokens 语义通道齐备（`packages/theme-tokens/src/styles.css`：classic light :122 / classic dark :182 / glass light :242 / glass dark :302 四块对称，`--background/--foreground/--muted/--muted-foreground/--accent/--border/--ring/--card/--success/--warning/--destructive/--info` 全在）且为 `:root[data-theme][data-mode]` 级 CSS 变量——`position:fixed` 面板虽挂 body 尾部，var 解析仍沿 DOM 到 `:root`，**直接消费语义令牌链无需新增任何依赖**（nop-debugger 不依赖 theme-tokens 包也成立，变量是 CSS 层事实）。V1 已交付 playground 运行时四态切换（`apps/playground/src/main.tsx:15` `applyTheme(readStoredTheme())`），双态验证的宿主开关现成。

### F3 code-editor-styles.css 暗色 fallback 令牌映射（定性修正后成立）

- 见 §0 勘误 1。残余面精确清单：`[data-theme='dark']` 块 24 个声明（:54-77）全部 raw（15 rgba + 9 hex）；`.nop-code-editor[data-fullscreen][data-theme='dark']` 表面 `var(--nop-code-editor-dark-surface, #1e1e1e)`（:90）；colorize 容器 dark 表面 `var(--nop-code-editor-dark-surface, #282c34)`（:290）。

- **触发器现状（裁决点背景）**：dark 覆盖块由组件 prop `editorTheme` 驱动（`code-editor-renderer.tsx:107` 默认 `'light'`，:243/:271 写容器 `data-theme` attr；colorize 路径由 `code-editor-renderer/colorize.tsx:98` 写 `data-colorize-theme`），**不读宿主 `data-mode`**——owner doc §10（design.md:161）明文契约："editorTheme 只负责编辑器内核/显式暗色覆盖路径"。kernel 侧同理：`editorTheme:'dark'` → oneDark（base.ts:163），否则 defaultLightTheme + 无语法高亮主题注入（:35-51/:165）。dark 宿主 + 未设 editorTheme 时 chrome 随宿主令牌变暗（light 令牌链自动翻转），但 kernel 高亮仍是 light 配色（见 R4）。
