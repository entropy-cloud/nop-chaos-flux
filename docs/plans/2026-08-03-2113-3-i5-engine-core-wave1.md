## Purpose

实现 `scada-canvas` 引擎核心 Wave 1：场景图适配层（I5.1）、视口与坐标变换（I5.2）、组态 JSON 解析与序列化（I5.3）、图元基类与基础形状（I5.4）——全部落在 `packages/flux-renderers-industrial/src/engine|serialization|symbols/` 域核心（无 React 依赖），纯逻辑层 Vitest 单测先行，为 I6 数据绑定与动画（Wave 2）提供可消费的引擎与图元模型底座。收口状态：I5.1–I5.4 全部完成、roadmap I5 回写 `done`。

## Current Baseline

- I2 设计文档已定稿并达成共识；`design-engine.md` §11 给出引擎拆分清单（scada-engine/tree-registry/viewport/config-adapter/hit/test-handle），§8.2 定义引擎命令句柄（applyAttrs/getSymbol/getSymbols/getSymbolProps/setSymbolProps/fit/center/setViewport/zoomAt/setSize/applyDiff/exportConfig/importConfig/getWorldPoint/getViewportPoint/destroy/reset，17 项 API 面），§8.3 定义测试句柄契约（`window.__flux_scada_<cid>`，含 engine/tree/app/getSymbol/getPointValue/getViewport/forceRender；句柄挂载/移除为引擎侧唯一所有权）。
- I1.2 spike 约束映射（gate-1-review §4）：A1（App/tree 创建参数写死 `tree: { type: 'viewport' }`）、A2（render 帧事件挂 tree 层、测试句柄含 tree 引用）、A3（10 万级命中无需空间索引，O(候选) 预检）、A5（引擎侧批量写语义 `applyAttrs`，上层合帧义务）。`design-symbols.md` §12.1：图元注册无 API 障碍（V5 自定义注册 20+ 图元目标以单测覆盖）。
- 依赖：I4.1 将提供包骨架与 `leafer-ui@2.2.9`/`@leafer-in/viewport@2.2.9`——**当前状态：I3/I4 前置 plan 均为 `draft`，`packages/flux-renderers-industrial/` 尚未落盘，`leafer-ui` 未入 pnpm-lock**；本 plan Phase 1 前置 Proof 项为硬门禁。
- 测试基建惯例：`vi.mock` 在既有包广泛使用（如 `flux-renderers-scheduling` 的 camera/i18n/flux-react mock 模式）；域核心纯逻辑测试用 happy-dom/node 环境（`vitest.shared.ts`）。
- 真正剩余的 gap：引擎代码全部未实现；包尚未落盘（I4 空壳也未存在）。

## Goals

- I5.1：`ScadaCanvasEngine` 类（`scada-engine.ts`）——create/destroy/reset 生命周期（A1 固化 viewport 类型）、App 三图层装配（ground/tree/sky）、tree 层 render 帧事件与 `onRender` 回调（A2）、节点索引 `tree-registry.ts`（id→Leaf + z 序）、测试句柄 `test-handle.ts`（`window.__flux_scada_<cid>` 挂载/移除，引擎侧唯一所有权）。
- I5.2：`viewport.ts` 纯逻辑坐标工具——`worldToViewport`/`viewportToWorld`/`fit`/`center`/`zoomAt`/`setViewport`/缩放钳制（minScale 0.1 / maxScale 20），全部 Vitest 单测。
- I5.3：`serialization/`（config-types/validate/parse/serialize/diff 纯逻辑，Vitest 单测）——契约对齐 `design-renderer.md` §4.3（validateScadaConfig/parseScadaConfig/serializeScadaConfig/diffScadaConfig → ScadaConfigDiff）。
- I5.4：`symbols/`（symbol-types/symbol-registry/style-resolver/symbol-factory/base-shapes/register-builtin）——`registerScadaSymbol`/unregister、8 种基础形状（rect/round-rect/ellipse/line/arrow/pipe/text/polygon）、样式解析（defaults ∪ 实例 ∪ statePatch）、按 tag 工厂实例化；V5 自定义注册（20+ 图元）→校验→实例化→卸载全路径单测覆盖。
- 场景树构建：`config-adapter.ts`（组态 JSON→leafer 场景树构建/销毁/重建/`applyDiff` 增量应用）——依赖 serialization 输出与 symbol-factory，故在本 plan 内置于 Phase 5（顺序落地说明见 Execution Plan）。

## Non-Goals

- 不实现点表模型/绑定解析/动画引擎/事件系统（属 I6）。
- 不实现视觉状态（选中/悬停/报警闪烁样式，属 I8.2）、复合图元 group/instance 深合并（属 I8.3）、设备/仪表/传感图元库（属 I9）。
- 不实现 React 桥接层（`use-scada-engine` 等 hooks 与 renderer 组件，属 I10.1）、点表↔flux 桥接（属 I10.3）。
- 不实现画布浏览交互（视口平移/缩放输入路径，属 I11.2；I5 只提供程序式视口 API 与纯逻辑坐标工具）。
- 不新增 leafer 之外的重型依赖（不引 node-canvas；测试用 vi.mock，真实浏览器渲染断言属 I13.1/I15.1 e2e）。

## Scope

### In Scope

- `src/engine/scada-engine.ts`：引擎类（创建/销毁/重建、三图层装配、A1/A2 固化、`applyAttrs` 批量写入口、命令句柄 API 面按 `design-engine.md` §8.2）。
- `src/engine/tree-registry.ts`：id→Leaf 索引与 z 序管理。
- `src/engine/test-handle.ts`：测试句柄挂载/移除（dev/test 下 `exposeTestHandle` + cid 键名；唯一所有权在引擎侧）。**I5 实现面**：engine/tree/app/getSymbol/getViewport（getViewport 经 I5.2 viewport 状态接线）/forceRender；`getPointValue` 依赖点表数据层（I6.1），显式延后（见 Deferred 条目，句柄结构为增量扩展，不构成契约缺口）。
- `src/engine/viewport.ts`：纯逻辑坐标工具（§4.4 清单）+ Vitest 单测。
- `src/serialization/`：config-types.ts（ScadaConfig/ScadaSymbolNode，供 schemas.ts 再导出；点表声明类型以本地结构形状定义，字段对齐 `design-data-binding.md` §4.1 `ScadaPointDeclaration`，I6.1 起由 binding/ 域再导出统一）、validate.ts、parse.ts、serialize.ts、diff.ts——全部 Vitest 单测（roadmap 测试纪律：纯逻辑层单测先行）。**parse 层语义**：`parseScadaConfig` 接受 string|object，字符串 JSON.parse 失败抛错/返回错误信号，桥接层（I10）映射为 onError（`design-renderer.md` §4.3）；非法 JSON 属 parse 层用例，validate 只接收对象输入。
- `src/engine/config-adapter.ts`：组态 JSON→场景树构建/销毁/重建/`applyDiff` 增量应用（依赖 serialization 输出 + symbol-factory，Phase 5 落地）。
- `src/symbols/`：symbol-types.ts（ScadaSymbolDefinition/ScadaSymbolProps，custom 字段以 TS 类型约束，`design-symbols.md` §12.2 审计约束）、symbol-registry.ts（register/unregister + 定义校验）、style-resolver.ts（状态样式解析纯逻辑）、symbol-factory.ts（type→leafer 节点，映射 `UICreator.get(tag)` 工厂）、base-shapes/（rect/round-rect/ellipse/line/arrow/pipe/text/polygon 8 形状）、register-builtin.ts（包加载注册基础形状）。
- 引擎生命周期与句柄的 focused 单测（`vi.mock('leafer-ui')` + `@leafer-in/viewport` side-effect mock 策略覆盖 wiring：create/destroy 幂等、句柄挂载/移除、applyAttrs 批量语义）。
- `docs/logs/2026/08-03.md` 记录产出。

## Test Strategy

档位选择：`必须自动化`——纯逻辑层（坐标/序列化/样式解析/注册表）是本 mission 的核心回归路径，roadmap 测试纪律明确「纯逻辑层单测先行」；Proof 项先于 Fix 项落地（每个模块先写失败测试再实现）。引擎 wiring（生命周期/句柄/批量写语义）以 `vi.mock('leafer-ui')` 覆盖——**mock 面以 I1.2 spike 实测真实 API 为锚**（`~/sources/industrial-hmi-research/spike-leafer/src/demo.js`：`new App({tree:{type:'viewport'}})`/`Group`/`Rect`/`tree.add`/`tree.on('render')`/`zoomLayer.move/scaleOfWorld/scaleX`/`selector.getByPoint`），`@leafer-in/viewport` 为 side-effect 导入需独立 mock/hoist 策略，最小化 mock↔真实漂移。真实浏览器渲染断言由首个可挂载页面（I13.1 demo）与正式 e2e 程序化断言补强（I15.1）承担，本 plan 不写 Playwright 用例（无 playground 页面可挂载，见 Deferred）。
