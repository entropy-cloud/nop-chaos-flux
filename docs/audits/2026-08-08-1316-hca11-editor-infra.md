## 3. P1/P2 finding 详述（Phase 2 修复输入）

### P1-1：importConfig 缺 engine.mode 同步（P1-08 parity 缺口，mode desync）

- **文件**：`packages/flux-renderers-industrial/src/editor/toolbox-runtime.ts:221-241`
- **证据**：
  ```ts
  const importConfigFn = (config: string | ScadaConfig): boolean => {
    try {
      const parsed = parseScadaConfig(config);
      const result = validateScadaConfig(parsed);
      if (!result.ok) { latest.current.onError?.('invalid-config', result.errors.join('; ')); return false; }
      resetSession(session, parsed);              // session.mode 强制 → 'edit'
      latest.current.onSelectionChange?.([]);
      synced.config = cloneConfigSnapshot(session.workingConfig);
      engine.build(session.workingConfig);        // engine.mode 不变（build 用 engine.mode 决定 editable 注入）
      notifySession();                             // ← 缺 engine.setMode(session.mode) 同步
      return true;
    } catch (error) { ... }
  };
  ```
  对照 `load()`（runtime-mutators.ts:216-221）有 `if (engine.currentMode !== session.mode) { engine.setMode(session.mode); }`（P1-08 落地）。
- **现状**：`resetSession`（editor-session.ts:78-84）无条件 `session.mode = 'edit'`。preview 态调 importConfig → session.mode='edit' 但 engine.mode 仍 'preview'（engine.build 不改 engine.mode，setMode 是唯一改 engine.mode 的路径）。两源 desync。
- **复现 trace**：
  1. mount（mode='edit'）→ engine.mode='edit', session.mode='edit'（mountEditorEngine P1-08 同步）
  2. switchMode('preview') → engine.mode='preview', session.mode='preview'（switchMode 双更新）
  3. toolbox.importConfig(newConfig) → resetSession → session.mode='edit'；engine.build（engine.mode 仍 'preview'）；**缺 setMode('edit')**
  4. 结果：session.mode='edit'（inspector/palette/connection-wiring `if (session.mode!=='edit') return` 守卫认为可编辑），engine.mode='preview'（画布无 Editor 装配、图元 editable:false、不可选中/变换）→ UI 与画布态失配
- **风险**：preview 态导入配置后，session 真相源说 edit 但画布实际 preview，用户看到不可编辑画布却面对编辑控件；connection-wiring 的 `session.mode` 守卫失效（session.mode='edit' 允许 pointerdown 连线拖拽，但画布 preview 态无 Editor / 图元不可交互）。违反 P1-08 已建立的 session/engine mode 一致性契约。
- **修复方向**：`importConfigFn` 在 `engine.build(session.workingConfig)` 后增 `if (engine.currentMode !== session.mode) { engine.setMode(session.mode); }`（与 load() 完全一致）。低成本（+2 行），无公共面变更。
- **failing-first proof**：见 Phase 2 新增 `scada-editor-canvas-ops.test.tsx`「importConfig syncs engine.mode to session.mode (P1-08 parity)」。修复前断言 `expected 'preview' to be 'edit'`（engine.currentMode 卡 preview），修复后转绿。

### P2-1：cloneConfigSnapshot + save 浅克隆 custom（扩展 P2 #4，R5 Layer 2 隔离缺口）

- **文件（根因点 a）**：`packages/flux-renderers-industrial/src/editor/editor-working-helpers.ts:79-83`（cloneConfigSnapshot 的 cloneNodeDeep）
- **文件（观测点 b）**：`packages/flux-renderers-industrial/src/editor/runtime-mutators.ts:191-202`（save committedBaseline）
- **证据**：
  ```ts
  // editor-working-helpers.ts:79-83
  function cloneNodeDeep(node: ScadaSymbolNode): ScadaSymbolNode {
    const clone: ScadaSymbolNode = { ...node };
    if (node.children) clone.children = node.children.map(cloneNodeDeep);
    return clone;                              // ← 未深克隆 custom（doc :63-69 声称 "deep-cloned"）
  }
  // runtime-mutators.ts:191-202
  const save = (): string => {
    session.committedBaseline = {
      ...session.workingConfig,
      symbols: session.workingConfig.symbols.map((n) => ({ ...n })),  // ← 浅克隆 symbols（共享 custom/children ref）
    };
    ...
  };
  ```
  对照 `editor-session.ts:cloneNode`（:123-129）有 `if (node.custom) clone.custom = structuredClone(node.custom);`（plan 2026-08-08-0900-1 P2 #4 落地）。
- **现状**：P2 #4 闭合了 `editor-session.cloneNode`（createScadaEditorSession / resetSession 入口）的 custom 深克隆，但同型浅克隆模式仍残留在 cloneConfigSnapshot（mutator prevSnapshot + synced.config）与 save committedBaseline 两处。save() 后 committedBaseline.symbols[i].custom === workingConfig.symbols[i].custom（共享 ref），违反 editor-session.ts:30-31 doc「working copy 变更不回流」+ createScadaEditorSession 已建立的 R5 Layer 2 隔离契约。
- **复现**：mount → writeConnection 改某 junction custom → save()（committedBaseline 浅克隆，custom ref 共享 working）→ 任一后续 in-place 改 working.custom.connections（如未来 mutator / 测试代码）→ committedBaseline.custom 被串改（baseline 不再代表"上次提交的基线"）。
- **风险**：当前 host mutator 整体替换 custom（`Object.assign(node, { custom: {...node.custom, connections} })`，runtime-mutators.ts:55-56 / editor-working-helpers.ts:160）→ 替换打断共享 ref → currently latent（diff 仍正确）。但契约已破：committedBaseline 不再保证 R5 Layer 2 隔离，cloneConfigSnapshot 的 doc 撒谎（声称 deep 实则浅）。任一未来 in-place custom 改动即触发串改，与 P2 #4 同型。
- **修复方向**：
  1. `editor-working-helpers.ts:cloneNodeDeep` 增 `if (node.custom) clone.custom = structuredClone(node.custom);`（与 editor-session.cloneNode P2 #4 同语义，对齐其 doc 声明）。
  2. `runtime-mutators.ts:save()` 改用 `cloneConfigSnapshot(session.workingConfig)`（现真深克隆）替代内联浅 `symbols.map((n) => ({ ...n }))`，单一深克隆真相源。
- **failing-first proof**：见 Phase 2 新增 `editor-session.test.ts`「cloneConfigSnapshot deep-clones nested custom (extends P2 #4)」+ `scada-editor-canvas-ops.test.tsx`「save committedBaseline isolates custom from working copy (R5 Layer 2)」。修复前断言 `expected custom to be isolated`（baseline.custom === working.custom 共享 ref），修复后转绿。

### P2-2（backlog）：connection-wiring pointerup 容器外释放卡死

- **文件**：`packages/flux-renderers-industrial/src/editor/connection-wiring.ts:58-60`
- **证据**：
  ```ts
  container.addEventListener('pointerdown', onConnectionPointerDown);
  container.addEventListener('pointermove', onConnectionPointerMove);
  container.addEventListener('pointerup', onConnectionPointerUp); // ← 容器级，非 window
  ```
  对照 `editor-adapter.ts:80` transform 事务 pointerup 挂 window + `{ once: true }`。
- **现状**：pointerdown 命中 junction → connectionDragActiveRef=true + beginDrag。若释放点在容器外（inspector/palette/browser 边缘），container pointerup 不 fire → onConnectionPointerUp 不触发 → connectionDragActiveRef 卡 true + endDrag 不调用（overlay 残留）。Editor transform（move/scale/rotate）持续被 handleGeometryChange 的 `if (connectionDragActiveRef.current) return` 抑制，用户无法平移图元直到下次命中 junction 的容器内 pointerup 循环。
- **风险**：连线端点拖拽是 niche 交互，"释放于容器外"概率低且可自恢复（下次 junction pointerdown→up 容器内即复位）；非数据损坏、非契约漂移、非高频路径。
- **裁定**：**P2 归 HCA-CR backlog**（非 plan P2 低成本）。理由（Why Not Blocking Closure）：fix 本身 ~10 行（pointerdown 时挂 window pointerup `{ once: true }` + cleanup 移除），但**可靠复现"释放于容器外"的 failing-first 回归测试需在 jsdom + leafer-mock 下构造跨元素 pointerup 派发，测试基础设施成本非平凡**，超出 plan「P2 低成本（<~30 行 / 单文件 / 无公共面变更）」bar。交互闭环变更按 plan Test Strategy 应追加 e2e（`scada-editor-interaction-correctness.spec.ts`），属 HCA-CR 跨层集中修复域。fix 方向已记录：模仿 editor-adapter.ts:80，pointerdown 命中 junction 后挂 `window.addEventListener('pointerup', endConnDrag, { once: true })`，endConnDrag 复位 ref + endDrag + 清 window listener；cleanup 兜底 removeEventListener + ref=false。
