## Purpose

修复设计器文档 `updateProps`/`importDocument` 同位重建时画布节点不随重编译模板刷新的缺陷，使"改了=看得见"的核心编辑回路成立。

## Current Baseline

- 候选链路（Round B 定位，未逐层证实）：设计器文档不带 `schema.id`，edit-assembly 仅投影 sid→testid（`packages/page-designer-renderers/src/.../edit-assembly.ts:30-32`）→ `createNodeId` 回退 path（`packages/flux-core/src/utils/schema.ts:34-40`）→ 同位重建 templateNode id/React key 不变 → 挂载期注册的 per-node 运行时状态（`node-renderer-resolved.tsx:81-135` 一带 propsProgram 注册）不随重编译刷新；`key={mode}` 整树重挂即恢复。
- 本缺陷可能是 flux-react 通用契约问题（"同 id 节点 props 重编译后是否重注册"）而非仅设计器——Phase 1 取证须判定归属（flux-react 核心 vs 设计器 id 方案）。
- **Phase 1 取证裁决（2026-10-22，执行会话）**：归属 **flux-react 契约层（Failure Path: core-contract）**。判别三层链（SchemaRenderer 直挂 / PageDesignerCanvas / 全 PageDesigner b08 流程）在缺省 vitest（无 React Compiler transform）下全部绿；同一测试在 playground 同款 `reactCompilerPreset({ target: '19' })` transform 下全部红；live Chromium（#/page-designer，fiber 取证）证实 NodeRendererResolved 已收到新 templateNode（propsProgram.label=新值）而 `useSyncExternalStoreWithSelector` 选中值停留旧值。根因位点：`packages/flux-react/src/use-sync-external-store-with-selector.ts`——React Compiler 把 `useMemo` 工厂内新建的可变 `memo` 对象提升为跨渲染复用的 memo-cache 槽位；`selector`/`isEqual` 身份变化创建新 `memoizedSelector` 闭包时，原实现靠工厂重跑获得全新 `memo`（hasMemo:false），编译产物沿用旧 `memo`（hasMemo:true + 旧 snapshot/selection）；静态节点 store 快照恒定（`() => null`），`objectIs(prevSnapshot, nextSnapshot)` 恒真 → selector 永不重跑 → 重编译 props 冻结。设计器 id 方案（path 派生 id + 同 key 复用）本身是合法的稳定性设计，非缺陷方。

## Goals
