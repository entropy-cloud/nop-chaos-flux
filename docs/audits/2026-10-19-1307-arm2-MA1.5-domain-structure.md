## P1 清单

### P1-MA1.5-001 · flux-renderers-3d 根 marker 缺失（裸 `three-canvas` 类名，零 `nop-*` 语义根 marker）

- **live 事实**：`packages/flux-renderers-3d/src/renderer/three-canvas.tsx:125` 根元素 `className={cn('three-canvas', className)}`——**3d 包全包零 `nop-*` marker 类**（`rg 'nop-'` 仅命中 `@nop-chaos/*` import 路径；`nop-3d` 在 packages/apps 零命中）。对照组全部实存根 marker：industrial `nop-scada-*` 族、graph `nop-graph`（:546）、map `nop-map`（:409）、basic `nop-container` 等。
- **为什么是 P1**（Rule 2「样式契约违反（marker 缺失/BEM 漂移/暗色失效）」明文点名 marker 缺失）：owner doc `renderer-markers-and-selectors.md` Root Marker Rules + Layer 2 规定根语义 marker 为渲染器身份锚点（`nop-` 前缀，样例 `nop-container`/`nop-page`/`nop-table`/`nop-chart`/`nop-field`）；3d 作为 9 个默认注册族之一（MA1.2 P1-MA1.2-001 场景下宿主可见）缺身份锚点，宿主 CSS/测试定位/审计工具均无法按契约寻址。
- **漏报机制佐证（工具盲区）**：`check:audit-missing-renderer-markers` 以 `content.includes('nop-')` 判有无（`scripts/audit/rules.mjs` 约 :144-149）——`@nop-chaos/*` import 路径即满足子串匹配，3d 文件结构性免检；**扫描器 0 ≠ 发射了 marker**（draft review R1/R2 双确认）。
- **修复方向**（供 MR 展开器）：three-canvas 根元素补 `nop-three-canvas`（或裁定的命名）语义 marker + 判别测试（旧实现无 marker 必挂）；同时修扫描器豁免逻辑（`@nop-chaos/` 路径不计入 marker 匹配）——后者可独立小批。
- **交叉引用**：MA7.3（样式维度）复用本证据；扫描器盲区归 MG/MA8.3 工具面。
