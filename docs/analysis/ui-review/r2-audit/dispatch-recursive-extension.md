## 递归扩展指令（第 N 轮）

以下是本审查前 N-1 轮已保存的全部发现：

- Round 01 全文: `docs/analysis/ui-review/r2-audit/round-01.md`
- Round 02..(N-1) 全文: 对应 `round-02.md` .. `round-0(N-1).md`（逐个完整读取）

你的任务：

1. 读取上述已有发现，理解已经覆盖了哪些组件、模式和交互路径。
2. 基于已有发现暴露的组件、模式和关联路径，**继续深挖**尚未覆盖的盲区（盲区清单，逐项对照）：
   - 已发现模式的**同类兄弟实例**（如某组件报了 focus ring 缺失，同包/跨包同型控件是否同病？修一处必须查全类）；
   - **跨组件组合场景**（表格+筛选+排序+分页组合、dialog 内嵌表单、popover 内嵌输入、tab 内嵌表格、抽屉内嵌滚动等组合使用时）；
   - **disabled / empty / loading / error 边缘态**（前轮可能只查了默认态）；
   - **响应式 / 移动端场景**（窄容器、移动布局、触摸目标）；
   - 已有发现涉及的组件是否有同类型问题未被检出；第 1 轮扫描中是否有尚未覆盖的组件或交互场景。
3. **只输出新发现的条目**。不要重复已有发现中已经报告的内容。
4. **去重自检**：输出前，将你的新发现与已有发现列表按**根因**比对。根因相同的合并或丢弃（即使表象不同）。`dispatch-shared-prefix.md` 的去重与边界规则（dedup-baseline §1-§4）继续生效。
5. 如果经过仔细检查后确实没有发现新的问题，按共享前缀的"零发现报告格式"输出（必须含检查范围 + 检查方法）。
6. 如果仍能找到零散细节，但这些细节只是低价值、机械重复、缺少明确用户影响，不要为了凑数量继续报告；输出："未发现新的高价值问题。审查结束。"（附检查范围与方法的简要说明）
7. 每个新发现仍需遵守统一发现格式（附录 A，编号 `[G{组号}-R{轮号}-视角{X}-{序号:02d}]`，如 `[G2-R2-视角3-01]`）。

输出义务（与第 1 轮一致）：全部发现写入派发指令指定的落盘文件；返回消息只含发现计数、覆盖率、静态口径声明（如有）、转 C2 候选（如有）、落盘文件路径。
