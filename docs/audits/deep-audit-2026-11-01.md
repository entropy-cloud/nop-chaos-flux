## 1. 环境根因：「807 Deferred 既有环境红 ELOOP」实为一条误建符号链接（✅ 复核并已修复）

- 现象：自 plan 807 起，多份 plan（810/811/812/813）收口均登记「layout contract-honesty ELOOP 系既有环境红，零交集」并以"触达面零新增红"口径放行 `pnpm test` exit 1。
- 根因：`.pnpm` 存储内 `@testing-library/react` 包目录中存在一条**自引用符号链接** `react -> <同目录自身>`（mtime 2026-10-31 07:04，非包内容），任何跟随符号链接的递归遍历都会无限下钻至 ELOOP。
- 修复：删除该链接（仅移除 node_modules 内一条链接，`pnpm install` 可复原）→ layout 25/25 文件、161 测试全绿（原先因加载失败少跑 3 个 contract-honesty 测试）。
- **但为什么 layout 的契约扫描会走进 flux-react 的依赖树？** 这暴露了真正的代码缺陷 T1（§2）：环境损伤只是触发器，扫描面错误才是让它变成门禁红的原因。
- 治理观察：一个红被连续 4+ 份 plan 以"环境红"登记放行而无人追根因，且 turbo 首个失败即中断后续任务——"零新增红"口径实际掩盖了 5 个未执行的测试任务。前向纪律建议：登记"环境红"时必须附根因证据或复现命令。
