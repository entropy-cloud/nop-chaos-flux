## 1. Findings

### P2-MA9.1-001 · 取消路径虚假 error toast 族（3 面，单根）— **新案 + MG 候选（单点修复）**

- **面 1（confirm 拒绝）**：用户拒绝确认框 → `notify('error','User declined the confirmation prompt.')`——`runtime-action-helpers.ts:155` `createCancelledResult` **未带 `failureHandled`**（对照 :169-170 ajax 路径同场景显式 `failureHandled: true` 并注释防双 toast）。
- **面 2（debounce 让位）**：同 key 双发 → 旧 dispatch 收 `{cancelled:true}` → 兜底 toast「Action failed」（action-execution.ts:377 → :175-212 通用失败分类）。
- **面 3（dispose 中止）**：页面卸载中止在途请求 → `notify('error','The operation was aborted')`（:208/:247 同缺标）。
- **单根**：`reportUnhandledFailureClass` 把一切未打标 failure 类结果（含三种良性取消）通用 notify——**MG 候选：cancelled 类默认豁免（单点修复同清 3 面）**。
- **执行者源码复核**：:155 无 failureHandled vs :170 有——对照成立。
- **定级 P2**：用户误报错误（信任损害），不丢数据不断链。

### P2-MA9.1-002 · pipe 语法 × 三元表达式静默变义/炸语法（3 形状，WA-formula-002 首个实漂移）— **新案**

- **形状 1**：`cond ? a : b | upper` → 静默变义为 `'X'`（期望 `'x'`——pipe 抢绑）。
- **形状 2**：`a | f(b ? 1 : 2)` → 按位或语义回落 `1`。
- **形状 3**：`cond ? a | upper : b` → compile 抛错且错误指向改写后文本。
- **根因**：`pipe-syntax.ts:15-113` `parseTopLevelFilterSegments`/`splitFilterArgs` 无三元感知（Round A node 直跑源码预证 + Round B 全 compile→eval 链确认）。
- **意义**：**WA-formula-002 watch（「防漂移」）的首个实漂移证据**——watch 升格依据。
- **定级 P2**：静默错误结果/误导性报错（无诊断）。

### P2-MA9.1-003 · 同模板多实例 debounce 键互踩 — **新案**

- **What**：同 templateNode.id 的多实例（表格两行）共享 debounce 键（action-core.ts:34-48 无实例区分）——行 A 动作被行 B 取消，并复合 P2-001 虚假 toast。
