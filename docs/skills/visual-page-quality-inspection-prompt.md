# 渲染页面视觉质量检查提示词（Visual Page Quality Inspection Prompt）

> **定位**: 本文档是一份面向 AI 的**页面级视觉质量检查提示词**——打开真实渲染的页面，以"用户看到的画面"为检查对象，对**交互 / 颜色 / 布局 / 间隔 / 排布**做逐页目检 + 程序化取证，覆盖浅色/深色双主题与交互中间态。
> **触发词**: 显示效果不达标、看着不对、页面很乱、间距不对、颜色不对、视觉走查、visual inspection、page-level visual QA
> **起源**: 2026-09-22 用户反馈——`visual-quality-roadmap.md` V0–V12f 已全部 done（一致性门禁 newHits=0、unit/e2e/check 全绿），但复杂页面与设计器页面的显示效果**体感仍不达标**。诊断：既有三个方法（ux-design-pattern-audit / complex-component-display-operability-audit / consistency-gate）全部以**代码或静态字面**为检查对象，没有任何一个方法以"渲染出来的页面"为检查对象；逐项修复的绿灯堆叠不等于页面整体达标。
> **执行要求**: 执行 agent 必须具备多模态读图能力（直接读截图评审）；pass/fail 判据必须程序化（AGENTS.md 2026-08-28 快照政策）。

## 方法论基线（2026-09 联网核实的外部最佳实践）

执行时以下列实践为判断基准，不必在发现中逐条引用出处，但严重度判级与"基准出处"栏应能落到其中一条：

| 来源                                                                                                | 采纳要点                                                                                                                                                                                                |
| --------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Design QA 十类清单**（OverlayQA 2026、CleverX、Saeloun 等 design-QA 实践汇总）                    | 每页按十类走查：间距（margin/padding 是否成体系）、排版（字号/字重层级）、颜色、对齐、**light/dark 双态**、交互态（hover/focus/error）、内容（截断/溢出/空态）、响应式、跨组件一致性                    |
| **WCAG 2.2**（W3C，2023-10 起）                                                                     | 2.4.11 焦点不得被遮挡（sticky 头部/悬浮层盖住焦点算缺陷）；2.5.7 所有拖拽功能必须有单指针替代途径；2.5.8 可点击目标最小 **24×24 CSS px**；1.4.3 正文对比度 ≥4.5:1；1.4.11 UI 组件边界/焦点环对比度 ≥3:1 |
| **迭代式多模态评审**（arXiv 2025 "Visual Prompting with Iterative Refinement for Design Critique"） | **禁止单轮"看图打分"**。每页评审必须三步：①自由 critique → ②对照本文件维度清单逐条 grounding（防遗漏与泛泛而谈）→ ③对每条目视发现做程序化取证。两次独立初评结论冲突的项，强制第三评                     |
| **NN/g 直接操作 + 拖放 UX**（nngroup.com；pencilandpaper.io 拖放指南 2024）                         | 画布/设计器页：可供性（可拖/可选/可缩放必须看得出来）、操作必须**增量且可逆**（有 undo 反馈）、落位必须有清晰 drop-target 反馈、吸附辅助线要"出现得及时、消失得干脆"                                    |

## 检查维度（对应用户抱怨的五词 + 三个横切）

每个维度 = 子项清单 + 程序化判据。逐页过 A–E，横切 F/G/H 按域汇总。

### 维度 A：交互

| #   | 检查项                                                                                 | 程序化判据                                                                                |
| --- | -------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| A1  | hover 态存在且可感知（行、按钮、卡片、链接）                                           | 强制 `:hover` 等效态后 diff 截图或读 computed style 变化                                  |
| A2  | focus-visible 有可见环，且**不被遮挡**（WCAG 2.4.11）                                  | `el.focus()` 后读 `outline`/`box-shadow`；`getBoundingClientRect` 与 sticky 头/悬浮层求交 |
| A3  | 可点击目标 ≥24×24（WCAG 2.5.8）                                                        | 遍历可交互元素 `getBoundingClientRect()`，统计 <24px 的短边                               |
| A4  | disabled 视觉可感知且 truly disabled                                                   | 读 `disabled` 属性 + computed `opacity`/`cursor`/`pointer-events`                         |
| A5  | loading 用 Spinner/Skeleton 非纯文本；empty 有意义提示非空白                           | 断言 Spinner/Skeleton DOM 存在；空态容器 innerText 非空                                   |
| A6  | 拖拽全链路视觉反馈：ghost 跟手、drop indicator 及时、落位/回弹有过渡                   | 拖拽中截帧（ghost 存在且偏移 <5px）；读 drop-indicator 元素 computed style                |
| A7  | 弹层打开态基本完整性：有关闭钮、遮罩、焦点落点正确（宽度/对齐/滚动的深度走查归维度 H） | 打开态截图 + DOM 断言（close button、focus 落点）                                         |
| A8  | 拖拽功能有单指针替代（WCAG 2.5.7）                                                     | 检查同一操作是否存在点击/按钮/菜单替代路径                                                |
| A9  | 交互后反馈可见（toast/状态变化/行闪烁），非静默更新                                    | 操作前后 DOM diff                                                                         |

### 维度 B：颜色

| #   | 检查项                                                                                                 | 程序化判据                                                                      |
| --- | ------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------- |
| B1  | 文本对比度：正文 ≥4.5:1、大字/次要 ≥3:1                                                                | 用 computed color 与实际背景色算 WCAG 对比度（叠层背景逐层合成）                |
| B2  | UI 组件边界与焦点环 ≥3:1（WCAG 1.4.11）                                                                | 同上，对象为 border/focus ring                                                  |
| B3  | 颜色语义正确：红=破坏性、绿=成功、黄=警示；同一语义跨页同色                                            | 抽取同类语义元素的 computed color 求一致性                                      |
| B4  | 走令牌不走字面：computed color 应可追溯到 `--nop-*`/语义令牌                                           | `getComputedStyle` 读值后 grep `theme-tokens/src/styles.css` 比对；字面色进发现 |
| B5  | **dark 平价**：light 下发现的问题在 dark 复检；dark 专有缺陷（纯白底块、不可读灰字、阴影失效）单独登记 | 同一探针在 `data-mode=dark` 下复跑，双份取证                                    |
| B6  | 状态色不裸奔：选中/告警/成功态不用默认蓝一键切                                                         | 读 selected/error 态类名与 computed color                                       |

### 维度 C：布局

| #   | 检查项                                                              | 程序化判据                                                                                 |
| --- | ------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| C1  | 无意外溢出：横向滚动条、文本溢出容器、画布被裁                      | `scrollWidth > clientWidth` / `scrollHeight > clientHeight` 全页扫描（排除有意滚动的容器） |
| C2  | 无意外重叠：浮层压内容、绝对定位元素压操作、标签压控件              | 关键元素对 `getBoundingClientRect` 求交（排除有意 overlay）                                |
| C3  | 主轴结构清晰：页头/侧栏/内容/工具栏分区可辨识，主内容占比合理       | 截图评审 + 主要区域 boundingRect 面积占比                                                  |
| C4  | 视口弹性：1280 与 ~800px 视口下不塌不挤（工具栏折叠、表格滚动合理） | 双视口截图对比 + C1 复跑                                                                   |
| C5  | sticky/固定元素不遮内容、不产生双滚动条                             | 滚动后截图 + 滚动容器计数                                                                  |
| C6  | 画布类：canvas 尺寸与容器一致（非写死宽高比导致拉伸/留白）          | `canvas.width/height` vs `getBoundingClientRect()`（DPR 换算）                             |

### 维度 D：间隔

| #   | 检查项                                                                                                                                                                                                                                                                                                                                                                                         | 程序化判据                                                                  |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| D1  | 垂直节奏成体系：同级块间距一致，落在 4/8pt 栅格（间距值 ∈ {4,8,12,16,24,32,48…}）                                                                                                                                                                                                                                                                                                              | 收集兄弟块 `boundingRect` 间隙值，报告非栅格值                              |
| D2  | 同组紧凑、异组留白：分组间距 > 组内项间距（格式塔邻近原则）                                                                                                                                                                                                                                                                                                                                    | 组内/组间间隙抽样对比                                                       |
| D3  | 密度合理：数据密集面（表格/看板/日程）行高与 padding 与行业密度档一致，不出现一行 triple-height 的异常行                                                                                                                                                                                                                                                                                       | 行高分布统计（离群行进发现）                                                |
| D4  | 工具栏/操作条内边距与项间距统一（跨页对比）                                                                                                                                                                                                                                                                                                                                                    | 抽样各页工具栏 computed padding/gap                                         |
| D5  | 表单面：label-control 间距、字段组间距、helper/error 文本间距成体系                                                                                                                                                                                                                                                                                                                            | 表单页间隙值收集                                                            |
| D6  | **分页器与宿主列表的间隔**：分页条与表格/列表底边有标准间隔（≥8px、落在栅格），不贴合；分页条自身行高与 padding 不挤。已知锚点\*\*：三个分页条已由 plan 490 收敛到同一块距令牌 `--space-block-gap`（12px，`TablePaginationBar`/`CrudListPagination`/`pagination-renderer` 根节点 + 表格 footer 槽）——本项复检口径不变：分页条 top − 宿主列表 bottom ≥ 8px 且落在栅格；若发现贴合回归按 D7 处理 | `paginationRect.top − tableRect.bottom ≥ 8`；跨表格/CRUD/列表分页条抽样对比 |
| D7  | **零间距贴死扫描**：同一容器内功能异组的兄弟块（工具栏↔内容↔底栏、卡片↔卡片、内容↔分页条）间隙 <4px 即进入人工复验（白名单制：有意 flush 须有 design.md/对标依据）                                                                                                                                                                                                                             | 兄弟块 boundingRect 间隙序列扫描，输出 <4px 组合清单                        |
| D8  | 边缘贴死：内容与直接容器边缘零 padding（卡片内表格贴边、弹层 body 贴边、面板内容贴边）                                                                                                                                                                                                                                                                                                         | `contentRect` 与 `containerRect` 边距采样                                   |

### 维度 E：排布（层级与动线）

| #   | 检查项                                                                                 | 程序化判据                                 |
| --- | -------------------------------------------------------------------------------------- | ------------------------------------------ |
| E1  | 首屏可答三问：这页是干什么的、主操作是什么、当前什么状态                               | 截图评审（3 秒内可答即过）                 |
| E2  | 视觉层级与重要性一致：主按钮 variant 强于次按钮、标题强于正文、关键数字强于标签        | 读主/次操作的 variant 类与字号字重对比     |
| E3  | 阅读动线顺：F/Z 动线上无关键信息被埋没；操作按钮落点符合惯例（确认在主位、取消在次位） | 截图评审 + 弹层按钮 DOM 顺序               |
| E4  | 对齐：同列元素左缘对齐、图标与文本基线对齐、数字右对齐                                 | 抽样元素 `boundingRect.x` 偏差 ≤1px        |
| E5  | 分组有视觉语言（卡片/分割线/留白三选一，不混用堆叠）                                   | 截图评审                                   |
| E6  | 空/首屏/结果三态都有任务引导，非"组件壳堆叠"                                           | 空态截图评审（对照 ux-skill 视角 11 口径） |

### 维度 F：跨页一致性（横切）

| #   | 检查项                                                                                                                        | 判据                                        |
| --- | ----------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------- |
| F1  | 同语义操作（新增/删除/筛选/分页/导出）跨页同图标、同 variant、同位置                                                          | 建立语义→表现矩阵表，逐页填充，偏差行即发现 |
| F2  | 同类面板（左侧树/右侧属性/底部日志）跨设计器同布局同宽度档                                                                    | 抽样 boundingRect                           |
| F3  | 同类空态/加载态跨页同模式                                                                                                     | 截图对比                                    |
| F4  | 术语与文案一致（同一概念不混用两种叫法）                                                                                      | 抽取页面关键文案比对                        |
| F5  | 同语义分页条跨组件一致：表格分页 / CRUD 列表分页 / 其他列表分页的间距口径（D6）、布局（左信息右按钮 vs 全靠右）、控件构成一致 | 各分页条 boundingRect + 类名结构对比        |

### 维度 H：弹层质量（Dialog / AlertDialog / Sheet / Drawer / Popover 专项）

> 用户高频痛点区：宽窄/大小失控、弹层内控件对齐、footer 按钮排布。弹层是"叠在页面上的一页"，按 H1–H9 逐项走查；每页至少打开 2 个不同弹层取证。

| #   | 检查项                                                                                                                                                                                                                                                                                                                                                                                                                                                              | 程序化判据                                                                                      |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| H1  | **宽度档位**：弹层宽度应有档位体系（sm/md/lg 或语义档），同类内容同档、跨页同档；桌面端无理由全屏宽、或内容被无理由压窄都算发现。**已知锚点**：ui Dialog/Sheet/Drawer/AlertDialog 已由 plan 490 统一到 `--overlay-size-*` 单调阶梯（`size` prop 唯一合法宽度入口，ad-hoc 宽度类由 `overlay-adhoc-width` 门禁拦截，契约见 styling-system.md「Overlay Size Ladder And Anatomy」）——本项复检口径不变：收集多页弹层宽度分布，核对是否落在阶梯档位上、同语义弹层是否同档 | 收集多页弹层 content `boundingRect.width` 分布；同语义弹层（确认/表单/详情）宽度档对照表        |
| H2  | **Drawer/Sheet 宽度档**：侧拉宽度与所载内容匹配（宽表单/属性面板被压窄、窄确认面板被拉宽都算）。**已知锚点**：ui Sheet/Drawer 默认 `sm` 档（plan 490 后 `sm:max-w-[var(--overlay-size-sm)]` 480px 封顶、窄视口 `w-3/4` 回退；复杂面板应由消费方显式传更大的 size 档）——承载复杂面板时是否够用，走查时按内容实测                                                                                                                                                     | Sheet/Drawer 打开态宽度 + 内容溢出扫描（C1 探针在弹层内复跑）                                   |
| H3  | **高度行为**：弹层高度 ≤ 视口（max-height 生效），长内容不把 footer 顶出屏幕                                                                                                                                                                                                                                                                                                                                                                                        | `contentRect.bottom ≤ innerHeight − 8`；长内容页复测                                            |
| H4  | Header 对齐：标题/描述/关闭钮基线与内边距统一；关闭钮不与标题、标签重叠                                                                                                                                                                                                                                                                                                                                                                                             | Header 区 boundingRect + 截图评审；关闭钮与标题 rect 求交                                       |
| H5  | **Footer 按钮排布**：操作按钮右对齐（确认在主位、取消在次位）、按钮间距走令牌、跨弹层一致；窄视口纵排（`flex-col-reverse`）后顺序仍正确                                                                                                                                                                                                                                                                                                                             | footer 容器 computed `justify-content`；按钮 rect 序 + 间距值（应收敛到 `--dialog-footer-gap`） |
| H6  | **Body 内控件对齐**：表单 label 与控件对齐方式统一（顶对齐/左对齐不混用）、字段垂直间距成栅格、helper/error 与控件间距一致                                                                                                                                                                                                                                                                                                                                          | 弹层内字段间隙序列（D1 探针在弹层内复跑）+ label/control rect 对齐采样                          |
| H7  | 三段节奏：header/body/footer 的 padding 成体系且跨弹层一致（body 走 `--dialog-body-padding-x` 令牌——核对消费面是否真正一致，有无弹层内嵌套弹层导致的双层 padding）                                                                                                                                                                                                                                                                                                  | 三段 computed padding 抽样跨弹层对照                                                            |
| H8  | 滚动契约：长内容滚动发生在 body 区（header/footer 固定可见），不是整个弹层滚动；body 滚动时 header/footer 不抖                                                                                                                                                                                                                                                                                                                                                      | 滚动弹层后截图对比 + `overflow-y` 归属元素断言                                                  |
| H9  | 响应式：窄视口下弹层不溢出视口、按钮组折行不破版、drawer 全宽的过渡合理                                                                                                                                                                                                                                                                                                                                                                                             | ~800px 视口重开弹层 + C1 探针复跑                                                               |

## 每页必查的状态矩阵

每个入选页面按以下矩阵截图 + 取证（可按页面域裁剪，裁剪要在 page card 里写明理由）：

```
主题态：light（必查）+ dark（必查）；glass 皮肤抽查
视口：1280×800（必查）+ ~800 宽窄视口（表格/移动/设计器页必查）
元素态：默认 → hover → focus-visible → selected → disabled（抽样）
中间态：弹层打开（Dialog ≥1 + Sheet/Drawer ≥1，有则必查；其中 1 个选长内容弹层验 H3/H8 滚动契约）→ 拖拽进行中（有拖拽的页面必查）→ loading/empty/error（有异步数据的页面必查）
```

截图不是证据本身——**每条发现必须附程序化判据**（下一节），截图用于定位与评审。

## 目视发现 → 程序化取证（强制转换）

目视发现必须转为下列可重跑的探针之一；确实无法程序化的，标注 `[visual-only]` 并强制进入独立复核（复核 agent 亲自看同一张截图判断）：

| 目视疑点            | 取证探针（page.evaluate 片段）                                                                                                                       |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| "间距乱/忽大忽小"   | `$$('.row,.card').map(e=>e.getBoundingClientRect())` 求相邻间隙序列，报告非 4/8 栅格值                                                               |
| "没对齐"            | 抽样元素 `x` 坐标序列，偏差 >1px 即坐实                                                                                                              |
| "颜色不对/不统一"   | `getComputedStyle(el).color` / `backgroundColor` 抽样 + 与令牌表比对 + WCAG 对比度计算                                                               |
| "点不动/没反馈"     | 操作前后 DOM snapshot diff + 事件监听存在性                                                                                                          |
| "溢出/挤爆"         | 全页 `scrollWidth>clientWidth` 扫描（白名单有意滚动容器）                                                                                            |
| "按钮太小"          | 可交互元素 `min(w,h)` 分布，<24 坐实                                                                                                                 |
| "焦点看不见"        | `el.focus()` 后读 `outlineWidth`/`boxShadow`，none 即坐实                                                                                            |
| "dark 下看不清"     | 双主题同名探针输出对照表                                                                                                                             |
| "画布拉伸/空转"     | `canvas.width` vs `clientWidth*dpr`；`toDataURL` 抽样像素非全零                                                                                      |
| "贴死/分页器贴表格" | 兄弟块间隙扫描：`[...parent.children].map(e=>e.getBoundingClientRect())` 求相邻 delta，<4px 组合输出（D6/D7）；分页条专项 = 分页条 top − 表格 bottom |
| "弹层宽度失控"      | 跨页收集弹层 content `boundingRect.width`，做同语义弹层宽度档对照表（H1/H2）                                                                         |
| "弹层按钮没对齐"    | footer 容器 computed `justify-content` / 首按钮 `margin-left:auto` 存在性；按钮间距值 vs `--dialog-footer-gap`（H5）                                 |

## 执行流程

### 阶段 0：Pre-flight

```
1. pnpm install && 启动 playground（4175 端口），确认 /#/home 可打开
2. 枚举路由清单（读 playground 路由注册，落 pages 起点表）
3. mkdir -p _tmp/visual-inspection-<date>/
4. 确认近期 docs/analysis/ 下无同主题未收口报告（避免重复）
5. 输出："环境就绪，共 N 页，开始 R1"
```

### 阶段 1：逐页走查（R1 广扫）

每页执行固定三步（迭代式多模态评审落地）：

```
① 自由 critique：打开页面 → 按状态矩阵截图 → 逐图写下目视疑点（不加过滤）
② 清单 grounding：对照维度 A–G 逐子项过一遍，补①遗漏项（清单子项逐条给 过/不过/不适用）
③ 取证：对每条目视疑点跑对应探针，坐实 → 进发现；证伪 → 进"误报排除记录"；无法程序化 → [visual-only]
```

每页产出一张 **page card**（`pages/<page>.md`）：截图清单 + A–G 子项勾选表 + 发现条目。

### 阶段 2：定向深挖（R2+，直至收敛）

- 输入 R1 全部 page card，按"维度 × 域"归并模式：同一模式跨页复现的，升格为**系统性发现**（一次修复收多页）。
- 对 R1 中 `[visual-only]`、存疑、以及"设计器 overlay"类高风险项定向复测。
- 终止条件：连续一轮无新发现，或新发现均为 LOW 且无系统性模式；上限 6 轮。

### 阶段 3：独立复核（强制，不得跳过）

- 复核 agent 必须是 fresh session；**必须重开页面重截同态截图、重跑探针**，不得只读发现文本后采信。
- 复核方式与 `ux-design-pattern-audit-prompt.md` 一致：先独立判断，再与发现比对；输出 保留/降级/驳回 逐条清单（`review.md`）。

### 阶段 4：汇总

`summary.md`：评分卡 + 系统性模式清单 + P0/P1 清单 + Quick Wins + 与既有台账（r2/r3 裁决池、audit-followups）的去重对照。发现若与已裁决 watch-only 项相同根因，标注引用并默认维持原裁决（推翻需给新证据）。

### 严重度判级

| 级别 | 定义                                                       | 示例                                                 |
| ---- | ---------------------------------------------------------- | ---------------------------------------------------- |
| P0   | 用户无法完成任务 / 功能在默认配置下不可用 / 关键信息不可读 | 拖拽落位不生效、dark 下正文不可读、画布内容整体错位  |
| P1   | 明显交互障碍或大范围视觉缺陷，高频路径必经                 | 主按钮 hover 无反馈、整页无 dark 适配、表格行高混乱  |
| P2   | 明显不一致、缺失的视觉反馈、系统性间隔/对齐偏差            | 同语义操作跨页不同色、组间距不成栅格、focus 环被遮挡 |
| P3   | 细节优化，用户可能注意到但不影响任务                       | 2px 间距偏差、次要图标语义可选歧义                   |

升降级：P2 出现在高频主路径（CRUD 删除、设计器保存）升 P1；P1 仅出现在一次性路径降 P2。系统性发现（≥3 页同根因）整体升一级。

## 执行注意事项

1. **判定永远双轨**：截图管"看到了什么"，探针管"算不算数"。只有截图没有探针的发现必须标 `[visual-only]` 并强制复核；只有探针没有目视的场景（如纯数值扫描）可以先行，但结论要回截图确认影响面。
2. **不与门禁抢活**：字面硬编码色/图标一致性由 `check:audit-ui-consistency-gaps` 管；本 skill 报告**渲染后**的新问题（computed 值、层叠结果、双主题平价、布局实测）。
3. **不修只报**：本 skill 是检查方法，产出 findings；修复走 roadmap/plan 生命周期（研究核实 → plan → 执行 → closure audit）。
4. **一次聚焦**：可只跑一个域（如只跑设计器域），page card 与评分卡按实际范围裁剪。
5. **闭环**：修复批次完成后，用本 skill 对同一页面清单做**复检轮**（同探针同截图位），summary 中给出前后对比，作为"显示效果达标"的验收口径——这是避免"修完仍不达标"的关键步骤。
