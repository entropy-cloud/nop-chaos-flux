## DOM 结构契约定稿 + 逐包审计路线图与 10 份计划建立（docs-only）

### 起因

用户提出渲染器 DOM 结构设计四原则并征求落地方式：①逐组件检查结构、无必要不嵌套；②确需嵌套时根节点带 `nop-<type>`（控件类型）+ `nop-renderer`（渲染器身份）双标记；③renderer 负责选择的子节点用 `data-slot` 区分；④设计器 frame 一律外置于组件外部，id 由控件 id 衍生（`nop-frame-${id}`）。

经对照 owner doc 与双代理全仓盘点后裁定：②中的通用 `nop-renderer` class 改为 **`data-renderer="<type>"` 属性**（FieldFrame 已有该属性且被冻结测试保护，收敛优于另立词汇，机器查询 `[data-renderer]` 更稳）；④的 id 衍生命名采纳，但锚点复用已有的 `data-cid`（AutoRenderer 已中央注入），frame 保持外置 overlay（page-designer CanvasOverlay 已是该架构，父级 wrapper 会破坏 flex/grid）。用户确认后落地。
